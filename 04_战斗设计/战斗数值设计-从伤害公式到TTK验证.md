# 战斗数值设计：从伤害公式到 TTK 验证

> 本文是对《游戏数值策划完全教程》第 1 章的独立凝练。原教程负责提供知识地图和练习方向；本文将它改写成一套实际做方案时可以直接使用的验证流程。

## 一、先确定战斗想让玩家感受到什么

战斗数值不是先决定“攻击力 100 还是 120”，而是先决定：

- 普通敌人希望几次攻击解决？
- 精英敌人希望玩家处理多久？
- Boss 的紧张感来自生命长度、机制、资源还是空间压力？
- 玩家一次普通失误会损失多少？
- 高操作能缩短多少时间？
- 角色差异主要来自面板、技能、位置还是资源管理？

建议先写 3 个体验锚点：

| 场景 | 目标 TTK | 玩家可犯的普通错误 | 主要压力来源 |
|---|---:|---:|---|
| 普通敌人 |  |  |  |
| 精英敌人 |  |  |  |
| Boss 阶段 |  |  |  |

没有体验锚点，后续的公式只是漂亮的数字容器。

## 二、伤害公式的选择

### 2.1 加法模型

一种常见形式是：

```text
伤害 = 攻击力 - 防御力
```

优点：直观、容易解释。缺点也很明显：

- 防御高于攻击时可能出现无效伤害；
- 高攻击和低防御的差距会被放大；
- 很难自然表达收益递减；
- 属性叠加后容易出现极端阈值。

适合强调固定数值、装备差异较小、规则简单的系统。使用时必须定义最小伤害、上限和穿透规则。

### 2.2 比例减伤模型

常见形式：

$$
Damage = ATK \times \frac{100}{100 + DEF}
$$

它的特点是防御收益递减：

- 防御从 0 增加到 100，影响很明显；
- 从 1000 增加到 1100，边际收益较小；
- 不容易出现“防御超过攻击就完全免疫”。

但它仍然不是万能公式。设计时要检查：

- 负防御是否允许？
- 防御穿透按加法还是乘法处理？
- 低攻击角色是否被压到没有有效输出？
- 取整是否在低伤害场景制造跳变？

### 2.3 混合模型

复杂游戏通常会组合基础值、倍率、固定伤害、场景修正和减伤：

```text
基础攻击
→ 技能倍率
→ 固定附加
→ 暴击/弱点
→ 防御减免
→ 场景修正
→ 取整
```

计算顺序本身就是规则。文档不能只写最终公式，必须写清每一层的输入、单位、上下限和取整位置。

## 三、不要只看面板伤害，要看期望和时间

### 3.1 期望伤害

如果暴击率为 `c`，暴击倍率为 `m`，基础伤害为 `B`：

$$
E[D] = B \times [1 + c(m - 1)]
$$

例如基础伤害 100、暴击率 25%、暴击倍率 2 倍：

$$
E[D] = 100 \times [1 + 0.25(2-1)] = 125
$$

这只说明长期平均值，不说明短期体验。还要看连续不暴击、爆发窗口和敌人是否会在一次暴击后直接跨过关键阈值。

### 3.2 TTK

最简单的近似：

$$
TTK \approx \frac{HP}{DPS}
$$

实际项目中要把以下因素加入模型：

- 攻击前摇和后摇；
- 技能冷却；
- 资源恢复；
- 移动和躲避损失；
- 目标无敌、护盾和阶段转换；
- 伤害浮动和暴击；
- 玩家操作失误。

因此更接近真实的表达是：

```text
有效战斗时间 = 输出时间 + 移动时间 + 机制时间 + 资源等待 + 失误成本
```

同样的面板 DPS，实际 TTK 可能因为机制时间不同而差很多。

## 四、属性系统必须有职责

每个属性至少要回答三个问题：

1. 它改变哪种玩家行为？
2. 玩家通过什么方式获得它？
3. 它和其他属性的关系是什么？

例如：

| 属性 | 主要改变 | 适合的玩家行为 | 主要风险 |
|---|---|---|---|
| 攻击力 | 稳定输出 | 正面压制 | 变成唯一最优 |
| 暴击率 | 输出波动 | 追求爆发 | 坏运气和阈值跳变 |
| 攻速 | 行动频率 | 持续输出 | 资源、触发和动画失控 |
| 穿透 | 对抗防御 | 针对特定目标 | 破坏坦克定位 |
| 生存 | 容错空间 | 稳定执行机制 | 战斗拖长 |

“属性很多”不等于“选择很多”。如果所有属性最终都只换算成同一个 DPS，玩家只是面对一张更长的计算表。

## 五、技能平衡看循环，不看单次截图

技能价值至少由以下因素共同决定：

```text
技能价值 ≈ 效果强度 × 覆盖率 × 命中可靠性
             ÷（资源成本 + 冷却成本 + 操作风险）
```

这不是固定行业公式，而是分析框架。需要分别测量：

- 单次释放价值；
- 一轮循环价值；
- 爆发窗口价值；
- 资源充足和资源不足时的价值；
- 单目标、群体和移动战中的价值；
- 高熟练度与低熟练度的差异。

常见事故是：单技能测试很平衡，连携后却形成无限循环；或者技能纸面 DPS 很高，但实战覆盖率极低。

## 六、验证流程

### 1. 合法性检查

- 概率是否在 0 到 1 之间；
- 防御、生命、成本是否允许负值；
- 冷却和资源是否可能变成 0 或负数；
- 所有 ID、技能和属性引用是否存在；
- 单位是否统一为秒、帧或毫秒。

### 2. 黄金样例

固定：角色、技能等级、目标属性、装备、随机种子和版本号。让表格和游戏内计算同时输出：

- 基础攻击；
- 技能倍率；
- 固定附加；
- 防御减免；
- 场景修正；
- 最终伤害；
- 每一步取整结果。

出现差异时，找第一个分叉点，不要直接改最终数字。

### 3. 边界测试

至少测试：

- 最低攻击对最高防御；
- 最高暴击率与暴击倍率组合；
- 0 冷却、满资源和资源枯竭；
- 负防御、护盾、免疫和反伤；
- 多个 Buff 同时触发；
- 连续暴击和连续不暴击；
- 单体、群体和移动目标。

### 4. 分布分析

报告均值之外，至少报告：

- P10 / P50 / P90 的 TTK；
- 连续失败次数；
- 一次攻击造成即死的概率；
- 不同 Build 的有效场景占比；
- 不同操作水平的结果差距。

## 七、战斗数值方案检查表

- [ ] 目标体验已经转成 TTK、容错、资源和压力指标
- [ ] 公式写明计算顺序、单位、上下限和取整
- [ ] 属性都有明确职责，不是单纯堆面板
- [ ] 暴击、闪避和掉落同时检查期望、方差和坏尾部
- [ ] 技能按循环、覆盖率和操作风险评估
- [ ] 已测试极端 Build 和跨系统组合
- [ ] 表格、客户端和服务端有黄金样例
- [ ] 版本改动能生成语义差异和影响报告
- [ ] 线上指标包含分层、版本和护栏
- [ ] 有止血、回滚和玩家补偿方案
