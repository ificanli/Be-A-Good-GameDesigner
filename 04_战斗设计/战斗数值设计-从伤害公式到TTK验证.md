# 战斗数值设计：伤害模型、输出循环与 TTK 验证

战斗数值设计需要把预期的战斗过程转化为可计算的规则。伤害公式只是其中一部分。完整模型还应包括行动频率、技能冷却、资源恢复、命中条件、敌人机制和玩家失误。设计工作的顺序应当从战斗时长与容错目标开始，再选择能够实现这些目标的参数。

## 1. 建立战斗基准场景

同一套伤害公式在普通敌人、精英敌人和首领战中承担的任务不同。开始计算前，应先定义若干基准场景。每个场景至少记录以下内容：

| 项目 | 说明 |
|---|---|
| 目标持续时间 | 从玩家取得控制权到敌人被击败的有效时间 |
| 输出窗口 | 玩家能够安全攻击的时间比例 |
| 失误容限 | 玩家可以承受多少次普通失误和严重失误 |
| 资源约束 | 技能是否受法力、怒气、弹药或充能限制 |
| 主要压力 | 时间、空间、资源、操作或信息中的哪一种占主导 |

例如，若一个精英敌人的目标持续时间为 30 秒，而玩家只能在 70% 的时间内有效输出，那么按面板 DPS 直接计算生命值会高估玩家伤害。用于标定生命值的应是有效 DPS。

$$
DPS_{effective}=DPS_{rotation}\times Uptime\times Accuracy
$$

其中，$Uptime$ 表示可输出时间比例，$Accuracy$ 表示攻击实际命中的比例。二者都应通过试玩或战斗日志估计，而不是长期固定为一个经验常数。

## 2. 选择伤害与防御模型

### 2.1 减法模型

减法模型的基本形式为：

$$
D=\max(A-D_f,D_{min})
$$

$A$ 为攻击侧结算值，$D_f$ 为防御侧固定减免，$D_{min}$ 为最小伤害。该模型便于玩家心算，每一点防御在单次攻击中减少固定伤害。但是，当攻击与防御接近时，防御的相对价值会迅速增大；防御超过攻击后，所有攻击可能同时落到最小伤害。

因此，减法模型适合数值区间较窄、攻击频率差异较小，并且设计者希望制造明显攻防阈值的游戏。若快攻与慢攻共用该模型，还要检查固定减免是否过度压制单次伤害较低的高频攻击。

### 2.2 比例减伤模型

常见的比例模型为：

$$
D=A\times\frac{K}{K+D_f}
$$

$K$ 是尺度参数。它并不是固定常数，而是决定防御值含义的标尺。当 $D_f=K$ 时，目标承受的伤害为原伤害的一半。改变 $K$，等于改变整个防御区间的效率。

此模型不会在有限正防御下产生完全免伤，并且绝对减伤比例随防御增加而趋缓。但“防御收益递减”需要说明观察口径：减伤百分比的增量会下降，而等效生命值在该公式下可保持线性增长。设计文档应明确讨论的是面板减伤、存活时间还是单位成本收益，不能混用。

负防御不能直接沿用正防御公式，因为当 $D_f$ 接近 $-K$ 时会出现奇点。若允许负防御，应单独定义负值区间的连续函数，并检查零点两侧的函数值和导数。

### 2.3 结算顺序

复杂系统通常采用分层结算：

```text
基础值
→ 技能系数与固定附加
→ 攻击侧增伤
→ 暴击或弱点判定
→ 防御、抗性与护盾
→ 场景修正
→ 伤害下限与上限
→ 取整
```

这只是示例顺序，不是通用标准。固定附加放在技能倍率之前还是之后，会决定它是否随技能成长；暴击放在防御前后，也会改变高防御目标承受的爆发。实现文档必须逐层记录输入、输出、单位、上下限和取整方式。

## 3. 从单次伤害扩展到输出循环

单次技能伤害只能用于比较一次命中。持续战斗需要计算技能循环：

$$
DPS_{rotation}=\frac{\sum_i D_iN_i}{T_{rotation}}
$$

$D_i$ 是第 $i$ 个行动的实际伤害，$N_i$ 是一个循环中的使用次数，$T_{rotation}$ 是从循环开始到系统回到可重复状态所需的时间。循环时间应包含施法、公共冷却、动画锁定、资源等待和必要移动。

建立循环表时，按时间顺序记录：

| 时间 | 行动 | 资源变化 | 冷却变化 | 伤害 | 状态 |
|---:|---|---:|---|---:|---|
| 0.0 | 生成技能 | +3 | 进入冷却 |  |  |
| 1.2 | 消耗技能 | -3 | 进入冷却 |  |  |
| 2.5 | 填充行动 |  |  |  |  |

该表可以发现纸面公式看不到的问题，例如资源溢出、技能同时冷却、循环无法闭合或某技能永久挤占其他技能。

## 4. 概率伤害的期望与分布

基础伤害为 $B$，暴击概率为 $c$，暴击倍率为 $m$ 时，单次攻击的期望伤害为：

$$
E[D]=B[1+c(m-1)]
$$

该公式只能比较长期平均输出。短战斗还需要考察方差和阈值。例如敌人剩余生命略高于普通伤害、低于暴击伤害时，暴击会直接改变所需攻击次数，平均伤害不能表示这种体验。

若每次判定独立，连续 $n$ 次不暴击的概率为：

$$
P(0\ crits)=(1-c)^n
$$

设计者应报告目标场景中的击杀次数分布或 TTK 分位数，而不是只报告均值。伪随机或保底会改变条件概率，使用后必须记录算法状态、重置条件和期望是否保持不变。

## 5. 用 TTK 检查战斗结果

静态近似为：

$$
TTK\approx\frac{HP}{DPS_{effective}}
$$

离散攻击中，最后一次攻击通常会产生溢出伤害，因此更准确的简单模型是先计算需要多少次命中，再根据攻击间隔求时间。持续伤害、阶段转换和多目标战斗则应使用时间步进或事件模拟。

至少建立三类样例：

1. **基准样例**：标准角色对标准目标，用于标定目标体验。
2. **边界样例**：最低攻击对最高防御、最高攻速、资源枯竭、负防御和伤害上限。
3. **极端构筑样例**：所有资源集中在暴击、防御、冷却或同一触发链上。

验证结果至少报告 P10、P50 和 P90 TTK。P10 过低可能产生秒杀，P90 过高则说明部分玩家会经历过长战斗。

## 6. 属性价值是局部量

属性权重不能脱离当前面板、目标和战斗场景。对于评价函数 $F$，属性 $x$ 的局部价值可用有限差分估计：

$$
W_x\approx\frac{F(x+\Delta x)-F(x)}{\Delta x}
$$

若 $F$ 取有效 DPS，得到的是输出权重；若 $F$ 取存活时间，得到的是生存权重。权重只在指定基准附近有效。达到暴击上限、技能冷却断点或资源循环阈值后，边际价值会改变，因此不能把一张权重表用于所有角色和所有版本。

## 7. 实现与回归检查

战斗计算应建立一个可重放的黄金样例。表格、客户端和服务端使用相同输入，逐层输出中间值。出现差异时，以第一个不同的中间值定位问题，而不是比较最终伤害后猜测原因。

发布前应检查：

- 所有概率、冷却和资源值的合法范围；
- 公式顺序、快照规则和取整位置；
- 同类增益采用相加还是相乘；
- 战斗日志能否还原每一步结算；
- 边界构筑是否突破伤害、减伤或行动频率限制；
- 目标 TTK 是否在不同操作水平和构筑下保持可接受分布。
