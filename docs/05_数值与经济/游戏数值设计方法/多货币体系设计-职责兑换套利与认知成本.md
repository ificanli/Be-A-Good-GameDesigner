# 多货币体系设计：职责、兑换、套利与认知成本

增加一种货币，等于在玩法和目标之间增加一层控制。它可以隔离进度、限定用途、引导玩家参与特定活动，也会增加学习成本、库存和兑换关系。货币数量不由游戏“重度或轻度”直接决定，而由项目需要隔离多少种资源流决定。

本章承接《资源经济设计》。前文处理资源总量、完成周期和库存，本章处理不同货币为什么存在、能否互换，以及多条价值关系如何保持一致。

## 1. 货币首先是一种权限

货币不只是数值容器。持有某种货币，表示玩家可以在一组特定商品或系统中进行选择。设计货币前应回答：

- 它允许购买或推进什么；
- 为什么不能直接使用现有货币；
- 它要隔离哪种进度或玩家行为；
- 玩家如何理解获得和使用它；
- 系统完成后，货币还有什么用途；
- 它能否交易、赠送、兑换或跨赛季保留。

若一种货币只有一个来源、一个出口，且使用时没有选择，它更接近计数材料。材料并非不能存在，但没有必要为了显得系统完整而包装成独立货币。

## 2. 常见货币职责

| 类型 | 主要职责 | 常见风险 |
|---|---|---|
| 通用软货币 | 支付多个日常系统，形成资源取舍 | 单一高效来源支配全部成长 |
| 付费货币 | 连接充值、商城和高价值服务 | 赠送与充值来源混用导致审计困难 |
| 绑定付费货币 | 提供福利和付费体验，不允许完整套现 | 与真实付费币名称相似造成误解 |
| 玩法代币 | 隔离某项玩法的奖励和进度 | 玩法毕业后长期积压 |
| 养成材料 | 控制某条成长线完成速度 | 种类过多、用途过窄 |
| 体力或门票 | 控制参与频率和自然时间进度 | 溢出、打卡压力和付费差距 |
| 声望或积分 | 记录参与和阶段资格 | 既做排名又做消费时目标冲突 |
| 交易货币 | 支持玩家市场和价值发现 | 工作室、财富集中和市场通胀 |
| 赛季货币 | 限定周期内的目标与商店 | 过期规则不透明造成资产损失 |

同一种货币可以承担多个职责，但职责越多，任何产出和价格调整影响的系统越广。通用货币提高自由度，也提高联动风险；专用货币降低联动风险，也提高认知和库存成本。

## 3. 什么时候应该增加新货币

增加前逐项检查：

1. 是否必须隔离某条成长线的速度；
2. 是否要保证奖励只能用于特定目标；
3. 是否要防止旧库存直接完成新内容；
4. 是否需要独立的赛季或玩法循环；
5. 现有货币的产出和消耗是否无法承接；
6. 玩家是否能在首次接触时理解其用途；
7. 系统毕业、版本结束和活动下线时如何退出。

如果只是希望玩家参加某玩法，可以使用首次奖励、周任务、掉落标签或兑换上限，不一定需要永久新增货币。如果只是希望控制购买次数，可以直接设置次数限制，不必再创造一张代币。

## 4. 货币关系图

多货币设计应画出来源、出口和兑换：

```text
玩法与付费来源
→ 货币或材料
→ 商店、养成与交易
→ 道具和能力
→ 分解、税费、过期或永久库存
```

每条兑换边记录方向、汇率、次数、条件和手续费。单向兑换与双向兑换的风险不同：单向兑换主要影响价值传导，双向兑换可能形成闭环套利。

建议建立矩阵：

| 从 / 到 | 金币 | 竞技币 | 制作材料 | 付费币 |
|---|---:|---:|---:|---:|
| 金币 | — | 禁止 | 商店购买 | 禁止 |
| 竞技币 | 禁止 | — | 限量兑换 | 禁止 |
| 制作材料 | 分解获得 | 禁止 | — | 禁止 |
| 付费币 | 固定兑换 | 活动限购 | 商城购买 | — |

矩阵可以快速暴露意外路径。例如付费币买材料、材料制作装备、装备分解金币、金币又能购买某项付费替代品，就可能形成价值回流。

## 5. 汇率不是日产量的简单倒数

若两种货币都通过同类玩法稳定获得，日产量可以作为初始锚点：

$$
Rate_{A\to B}^{time}=\frac{DailyB}{DailyA}
$$

它表示投入相近时间时的机会成本，不等于真实价值。还需考虑：

- 用途是否刚需；
- 当前库存和毕业比例；
- 获取是否受次数、能力或社交条件限制；
- 是否可交易和套现；
- 不同玩家阶段的边际需求；
- 随机性和坏尾部；
- 兑换本身的次数与手续费。

因此，汇率应按具体用途验证。某物品同时用 A、B 两种货币出售时，可以用时间锚点给出初价，再检查两条购买路径的目标完成天数、玩家库存和机会成本。

## 6. 商品定价从获得周期和机会成本出发

设商品目标获得周期为 $T$ 天，目标玩家该货币每日可自由支配量为 $S$，价格初值为：

$$
Price=T\times S
$$

这里应使用扣除基础必需消耗后的可支配量，而不是全部日产量。若玩家每日获得 10,000 金币，但基础升级平均消耗 8,000，则用 10,000 计算二十日商品，会严重低估真实等待。

同一商店还要检查商品之间的机会成本。玩家购买一个长期目标后，会放弃多少日常材料？限量商品是否总是优于常驻商品？若某商品性价比全局最高且周期刷新，它会成为必买税，商店选择只是形式。

价格数字美化后，需要重新计算实际获得周期。定价从 198,000 调到 200,000 看似微小，在低日产量或限时商店中可能跨过一个完整结算周期。

## 7. 兑换与套利检查

对任意闭环，计算一单位起始资产经过所有兑换后的返回量。若：

$$
Return=\prod_i Rate_i\times(1-Fee_i)>1
$$

且路径可以重复执行，就存在确定性套利。随机制作和分解则比较期望返回及高分位结果，还要考虑次数、时间和市场价格。

套利检查至少覆盖：

- 商店购买后分解；
- 制作后出售或回收；
- 货币兑换后购买同类商品；
- 玩家交易与系统回收价；
- 折扣、活动加成和返利叠加；
- 跨服、跨角色和账号共享；
- 新旧版本材料转换。

手续费可以降低套利，但不应替代正确的价值关系。为了压制异常价格而设置难以解释的动态惩罚税，可能伤害正常交易和市场信任。

## 8. 付费币与赠送币应可审计

充值获得、系统赠送和活动补偿的货币，成本和法律含义可能不同。即使界面名称相近，后台也应能区分来源、消费优先级、退款和转移规则。

设计时明确：

- 充值币和赠送币能购买哪些商品；
- 混合余额消费时先扣哪一种；
- 退款如何追溯已消费资产；
- 玩家交易是否允许带出付费价值；
- 跨区、合服和账号迁移如何处理；
- 付费商品分解后返回什么资产。

不要让赠送币经过多步兑换后变成可交易或可退款的充值价值。每条价值路径都要可追踪。

## 9. 体力、门票和次数货币

体力本质上是随时间恢复的参与权限。需要记录恢复速度、上限、溢出、补充、储存和消耗场景。理论日产量为恢复速率乘时间，但实际产量受登录频率和上限影响。

门票把参与权存入物品，可以允许玩家延后消费，也可能形成囤积和爆发刷取。次数则最直接，但错过后通常无法保存。三种方式适合不同目标：

- 体力：控制总参与量，同时允许玩家选择内容；
- 门票：控制特定内容，并允许有限储存；
- 次数：控制固定玩法频率，规则最简单。

如果项目同时使用体力、门票和每日次数限制同一玩法，约束可能重复。玩家需要同时管理三道门槛，却没有增加有效选择。

## 10. 玩家交易和系统货币

自由交易会让资源价值由玩家供需决定。系统固定价仍然影响市场，因为它提供价格上限、下限或退出渠道。

交易经济应观察：

- 货币净产出和系统销毁；
- 核心商品成交价、成交量和挂单深度；
- 财富和资源集中度；
- 新玩家购买基础商品所需时间；
- 工作室和自动化行为的产出占比；
- 跨服与合服造成的供需变化。

交易税的作用是回收货币和提高套利成本，不保证价格回到设计者认为的“正常汇率”。价格偏离可能来自真实供需变化。动态税率若缺乏透明规则，会降低交易意愿。

## 11. 完整算例：三货币商店

假设项目有金币、竞技币和绑定钻石：

| 货币 | 普通日产量 | 基础日消耗 | 可支配量 | 主要职责 |
|---|---:|---:|---:|---|
| 金币 | 50,000 | 35,000 | 15,000 | 通用养成 |
| 竞技币 | 1,000 | 0 | 1,000 | 竞技奖励选择 |
| 绑定钻石 | 120 | 40 | 80 | 福利与便利 |

一个目标周期为十天的养成材料包，若分别用三种货币出售，初价可以按可支配量估算为 150,000 金币、10,000 竞技币或 800 绑定钻石。

但这三个价格不一定等价。竞技币只能通过竞技获得，购买材料会放弃赛季外观；绑定钻石可购买更多便利；金币还要应对临时强化需求。设计者需要比较三条路径的机会成本，而不是直接宣布固定汇率。

若材料包分解可获得 60,000 金币，则竞技币购买再分解相当于 10,000 竞技币兑换 60,000 金币。若系统另有 1,000 竞技币兑换 8,000 金币的途径，玩家会选择后者；反过来若分解返回 100,000，就可能让材料包成为更优兑换通道。关系矩阵可以发现这种隐性汇率。

## 12. 货币失效和毕业处理

货币失效通常来自用途完成，而不只是产出过多。处理方式包括：

- 增加不影响核心平衡的长期出口；
- 允许兑换为通用但折价的资源；
- 系统毕业后停止或降低掉落；
- 提供收藏、外观或社交用途；
- 合并旧版本材料；
- 在规则透明的赛季中回收或转换。

定期清零永久货币会破坏资产信任，不应作为常规通胀手段。只有货币从一开始就明确属于赛季、过期时间可见、转换规则稳定时，周期重置才是合理规则的一部分。

## 13. 认知成本与界面表达

玩家需要知道货币从哪里来、能买什么、是否值得保存。货币过多时，即使经济模型没有错误，玩家也会因为无法比较而放弃规划。

降低认知成本的方法包括：

- 同一系统只突出一到两种主要资源；
- 货币图标、颜色和名称保持明显区别；
- 在消耗界面直接显示获取入口和预计缺口；
- 对即将过期或版本转换的货币明确提示；
- 合并功能相同、周期相近的旧代币；
- 在商店中显示限购周期和刷新规则；
- 不用极其相似的名称区分充值币与赠送币。

新增货币前可以做一个简单测试：不看策划文档，玩家能否用一句话说明其来源和主要用途。如果团队内部也需要翻表才能回答，这种货币的职责通常不够清楚。

## 14. 线上指标与诊断

建议按货币观察：

- 来源和出口占比；
- 玩家分层的获得、消耗和库存分布；
- 获得后到首次消费的时间；
- 商店各商品购买率和放弃关系；
- 兑换路径和隐含汇率；
- 交易价格、成交量和财富集中；
- 毕业玩家的积压速度；
- 过期、转换和清退造成的损失。

| 现象 | 优先检查 |
|---|---|
| 玩家不知道货币用途 | 职责、开放教学和界面入口 |
| 某代币长期不用 | 商店价值、毕业比例和刷新周期 |
| 所有人只买同一商品 | 相对性价比和周期必买压力 |
| 兑换价频繁失真 | 日产量、用途、库存和市场需求 |
| 交易量下降但税收提高 | 手续费是否抑制正常交易 |
| 赠送币出现可套现路径 | 购买、分解、交易和退款链 |
| 新活动代币越积越多 | 退出、转换和停止掉落规则 |
| 新货币上线后旧玩法失效 | 是否隔离了原有价值和奖励用途 |

## 15. 工作簿结构

建议拆为：

1. 货币字典：职责、来源、出口、流通和过期；
2. 货币关系矩阵：兑换方向、汇率、次数和费用；
3. 玩家分层产销：理论、目标和实际获得；
4. 商店定价：目标周期、可支配量和机会成本；
5. 体力与门票：恢复、储存、溢出和补充；
6. 交易市场：系统价、税、成交和财富分布；
7. 套利检查：购买、制作、分解和兑换闭环；
8. 版本迁移：过期、合并、补偿和停止掉落；
9. 监控页：库存、购买率、隐含汇率和失效货币。

## 16. 发布前检查

- [ ] 每种货币是否有无法被现有货币替代的职责？
- [ ] 来源、出口、储存、流通和毕业处理是否完整？
- [ ] 是否画出所有兑换和回流路径？
- [ ] 汇率是否只把日产量当初始锚点，而非绝对价值？
- [ ] 定价是否使用可支配量和目标获得周期？
- [ ] 是否检查购买—制作—分解—交易的闭环套利？
- [ ] 充值币和赠送币是否可审计、可退款追溯？
- [ ] 体力、门票和次数是否存在重复约束？
- [ ] 赛季过期和永久资产是否清楚区分？
- [ ] 玩家能否快速理解每种货币的来源与用途？
