# 等级与经验设计：从成长时间表到进度追赶

等级系统安排玩家以什么速度通过游戏阶段。玩家不会直接感受经验公式的曲线类型，他们感受到的是多久升一级、今天做哪些内容、何时解锁新能力，以及落后后需要多长时间才能回到主要内容。因此，经验表应从成长时间表开始，再根据经验来源反推每级需求。

本章主要处理角色等级和长期进度。装备、技能等独立养成线如何提供战斗能力，另见相关专题；玩家能力如何转成怪物和关卡强度，见《玩家成长与内容梯度设计》。

## 1. 先制作成长时间表

成长时间表以阶段为单位，记录玩家从创建角色到进入当前主要内容所经历的时间、等级和解锁。阶段边界通常来自玩法变化，而不是为了让公式整齐而均分等级。

| 阶段 | 目标累计时间 | 主要行为 | 新增内容 | 设计目的 |
|---|---:|---|---|---|
| 教学阶段 | 分钟级 | 主线、教学战斗 | 基础操作、首个技能 | 快速建立操作与目标 |
| 系统展开 | 小时级 | 主线、支线、首次副本 | 装备、养成、社交 | 逐步增加决策量 |
| 稳定成长 | 天级 | 日常、挂机、活动、副本 | Build 与长期目标 | 形成稳定玩法结构 |
| 当前版本 | 周或赛季级 | 高难、收集、竞争 | 版本内容 | 承接长期参与 |

表中的时间应区分三种口径：

- **自然时间**：从注册到达成目标经过多少天；
- **有效游玩时间**：玩家实际投入多少小时；
- **受限时间**：每日次数、体力、定时活动等门槛带来的等待。

同样是三天升到目标等级，一名玩家可能实际玩十二小时，另一名玩家每天完成半小时日常即可到达。若不区分口径，后续无法判断问题来自经验总量、玩法效率还是时间门槛。

## 2. 从升级时间反推每级经验

设玩家在等级 $L$ 的综合经验效率为 $R_L$，目标升级时间为 $T_L$，则该级经验需求的初值为：

$$
EXP_L=R_L\times T_L
$$

这个公式用于把“希望这一阶段持续多久”转换为经验配置。$R_L$ 不能只取最高效率玩法，也不能只取怪物击杀经验。它应表示目标玩家在该阶段真实可获得的综合效率。

若经验来自多个活动，可写为：

$$
R_L=\sum_j F_{j,L}\times D_{j,L}\times E_{j,L}\times P_{j,L}
$$

其中：

- $F_{j,L}$：活动在统计周期内可参与的次数；
- $D_{j,L}$：单次参与时间；
- $E_{j,L}$：活动单位时间经验效率；
- $P_{j,L}$：目标玩家的参与或完成比例。

如果使用“每日经验”而不是“单位时间经验”，可以直接计算各活动的单日贡献，再用目标升级天数反推需求。关键是所有变量采用同一统计周期。

### 一个简化例子

某阶段的普通玩家每天完成：

| 来源 | 单日经验 | 预计参与率 | 计入经验 |
|---|---:|---:|---:|
| 主线与支线 | 12,000 | 90% | 10,800 |
| 日常任务 | 8,000 | 80% | 6,400 |
| 副本 | 6,000 | 60% | 3,600 |
| 自然挂机 | 5,000 | 100% | 5,000 |

综合单日产出为 25,800。若希望该等级平均持续 1.5 天，则需求初值为 38,700。这个数仍需经过内容解锁、失败率和整数美化检查，不能直接作为最终配置。

## 3. 经验需求和经验产出必须同时建模

只提高每级需求会延长所有玩家的升级时间，但不会说明玩家应该通过哪些行为完成成长。经验来源的份额会塑造实际玩法：

- 挂机占比过高时，主动玩法对进度影响很弱；
- 定时活动占比过高时，错过时间窗口会造成明显落后；
- 单一副本效率过高时，它会成为事实上的必做内容；
- 主线经验刚好填满升级需求时，玩家一旦漏做内容就可能卡住；
- 付费经验来源与基础产出相乘时，差距会随时间扩大。

因此，每个阶段至少需要一张经验来源构成表：

| 来源 | 单次效率 | 次数或持续时间 | 单日总量 | 占比 | 是否可补领 | 是否受等级修正 |
|---|---:|---:|---:|---:|---|---|
| 主线 |  |  |  |  |  |  |
| 日常 |  |  |  |  |  |  |
| 副本 |  |  |  |  |  |  |
| 活动 |  |  |  |  |  |  |
| 挂机 |  |  |  |  |  |  |

设计者应分别计算高活跃、普通、低活跃和回流玩家，而不是只保留一个“标准日产出”。标准值负责标定，玩家分层负责检查分布。

## 4. 曲线用于连接阶段，不用于代替阶段设计

完成各阶段的目标时间和经验产出后，可以使用公式减少逐级配置量。常见形式有：

- 线性：$EXP_L=a+bL$；
- 多项式：$EXP_L=aL^p+b$；
- 指数：$EXP_L=ar^L$；
- 分段函数：不同等级段采用不同参数或不同公式。

选择函数时，应比较实际输出，而不是根据名称判断“线性平缓、指数陡峭”。在有限等级区间内，多种函数可能产生近似结果。真正需要检查的是：

1. 每级升级时间是否符合阶段目标；
2. 累计时间是否符合内容计划；
3. 阶段连接处是否出现突增或突降；
4. 调整参数后，影响范围是否可控；
5. 数值取整后是否出现连续多级不变或异常跳点。

长线项目通常更适合分段设计。教学阶段、系统展开阶段和长期阶段承担的任务不同，强行用一条公式贯穿全等级，会使局部调整牵动整条曲线。

## 5. 把等级、关卡和系统开放放到同一时间轴

等级不是孤立进度。一个可落地的成长模型应把以下内容连接起来：

```text
累计自然时间
→ 玩家等级
→ 可参与玩法与每日经验来源
→ 主线或关卡位置
→ 系统开放与养成投放
→ 目标玩家能力
→ 内容难度
```

例如，提高某阶段的经验副本占比，会让参与玩家更早进入后续关卡；后续关卡若同时投放装备材料，玩家能力又会进一步提前。只修改经验表而不检查关卡、系统开放和资源投放，可能产生连锁偏移。

项目表中可以为每个等级记录：

| 等级 | 单级时间 | 累计时间 | 单级经验 | 累计经验 | 主要经验来源 | 对应关卡 | 新开放系统 |
|---:|---:|---:|---:|---:|---|---|---|
|  |  |  |  |  |  |  |  |

等级很多时，不必手工配置每一行。可以用阶段参数生成逐级结果，但输出表必须能显示每一级的实际时间和对应内容，便于检查。

## 6. 累计投入用于版本迁移和追赶

达到等级 $L$ 的累计经验为：

$$
C(L)=\sum_{n=1}^{L-1}EXP_n
$$

等级编号只表示玩家位于哪一段，累计经验才记录其在该进度线上的投入。修改经验曲线时，直接把旧等级映射到同名新等级，可能导致投入增加或损失。

一种常见迁移方式是：

1. 计算玩家旧等级和当前级经验对应的累计投入；
2. 在新曲线中寻找不超过该投入的最高等级；
3. 将剩余经验放入新等级的当前进度；
4. 对整数舍入造成的差额进行对账；
5. 等级解锁、付费权益和任务状态另行映射。

经验只是玩家资产的一部分。若旧等级同时代表装备门槛、技能点和内容资格，迁移时需要逐项检查，不能用累计经验替代全部资产。

## 7. 追赶机制应缩短到达当前内容的路径

追赶的衡量单位应是“新玩家或回流玩家到达当前主要内容需要多久”，而不是单独看经验倍率。玩家可能等级已经追上，却仍缺少装备、技能、材料或前置任务。

常见的追赶手段包括：

- 降低旧阶段经验需求；
- 提高旧阶段经验和材料产出；
- 根据落后程度提供递减的经验加成；
- 合并过时任务和系统门槛；
- 提供旧装备或关键能力的定向获取；
- 允许错过的限时产出通过其他方式补回。

追赶不等于立即抹平所有差距。设计时要明确哪些差距可以缩短，哪些用于保留长期投入价值。例如，进入组队内容的基础能力可以快速追赶，而收藏、外观和高阶构筑仍可保留历史积累。

## 8. 长期增长需要同时检查内容寿命

角色能力持续提高时，旧内容的相对难度会下降。成长速度是否健康，不能只看玩家战力增长率，还要看内容被跨越的速度。

建议持续记录：

- 新版本普通玩家到达主要内容的天数；
- 各阶段单级时间和累计时间；
- 各经验来源的实际占比；
- 不同活跃层玩家的等级分布；
- 旧内容被跳过或碾压的比例；
- 等级追上后，装备和技能仍需补齐的时间；
- 版本修改前后的累计投入差额。

不存在适用于所有项目的固定月度成长率。赛季制游戏可以周期性重置，长期养成游戏则需要控制复利和旧资产替代速度。判断标准应来自版本周期、内容供应能力和玩家回流路径。

## 9. 工作表结构

一个可维护的等级经验工作簿可以分成五层：

1. **阶段输入**：等级段、目标时间、活跃假设和解锁节点；
2. **产出输入**：活动次数、时长、效率、参与率和补领规则；
3. **逐级计算**：单级经验、累计经验、单级时间和累计时间；
4. **内容映射**：关卡、玩法开放、资源投放和能力阶段；
5. **检查输出**：阶段跳点、来源占比、玩家分层和迁移差额。

不要把阶段参数、逐级结果和人工修正混在一张表里。输入与输出分开后，才能知道某个异常来自目标修改、公式错误还是手工覆盖。

## 10. 发布前检查

- [ ] 每个成长阶段是否有明确的目标自然时间和有效游玩时间？
- [ ] 每级需求是否由目标时间和真实经验来源反推？
- [ ] 是否分别计算高活跃、普通、低活跃和回流玩家？
- [ ] 是否检查某项活动被经验效率推成事实上的必做内容？
- [ ] 阶段连接处是否存在升级时间突变？
- [ ] 等级、关卡、系统开放和玩家能力是否位于同一时间轴？
- [ ] 版本迁移是否按累计投入对账？
- [ ] 追赶是否同时覆盖经验、装备、技能和任务门槛？
- [ ] 是否能从配置表追溯每个等级的参数来源？
