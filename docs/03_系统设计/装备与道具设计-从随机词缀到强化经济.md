# 装备与道具设计：从随机词缀到强化经济

> 本文是对《游戏数值策划完全教程》第 3 章的独立凝练。核心问题不是“词缀有多少种”，而是装备是否让玩家产生可理解、可比较、可追求、可放弃的选择。

## 一、装备系统的四个任务

装备通常同时承担四件事：

1. **成长载体**：把时间、战斗和资源转化成能力。
2. **选择载体**：让玩家在不同属性、场景和 Build 之间取舍。
3. **内容消耗器**：为副本、探索、交易和长期目标提供理由。
4. **身份表达器**：让玩家展示风格、稀有收藏和投入程度。

如果装备只有第一项，玩家会把所有物品按“数字更大”排序；如果随机性没有带来选择，系统就只是在生产垃圾和清理垃圾。

## 二、先定义装备的决策空间

设计装备前先回答：

- 玩家是在选择一件装备，还是筛选一堆掉落？
- 装备差异是纵向强度，还是横向玩法？
- 玩家是否需要为不同场景准备多套装备？
- 装备能否交易、锁定、拆解或继承？
- 追求目标是毕业、收藏、实验 Build，还是社交展示？

装备系统的深度来自玩家有理由保留两件不同的装备，而不是拥有 200 件只有一件值得用的装备。

## 三、稀有度：建立期待，不要只做颜色

稀有度通常包含四层含义：

| 层次 | 设计问题 |
|---|---|
| 获取稀缺性 | 玩家多久能见到一次？ |
| 能力差异 | 它改变强度还是改变玩法？ |
| 信息价值 | 玩家一眼能否理解它为什么特殊？ |
| 社会价值 | 它是否代表成就、身份或收藏？ |

稀有度越高，不一定必须面板越高。更健康的结构通常是：

- 普通装备：稳定填补成长缺口；
- 稀有装备：提供较明确的方向；
- 史诗装备：改变技能或玩法组合；
- 传说装备：形成追求目标，但不必在所有场景绝对最优。

如果稀有度只等于更高的基础属性，旧装备会快速失效，内容也会被单一的纵向成长吞掉。

## 四、随机词缀：控制三种随机性

### 4.1 词缀种类随机

决定出现哪些属性。它影响 Build 命中率和装备辨识度。

### 4.2 词缀数值随机

决定属性落在区间中的哪个位置。它影响追求极值的深度和刷取成本。

### 4.3 词缀组合随机

决定多条属性如何同时出现。它最容易产生组合爆炸和不可控的极端 Build。

三种随机性叠加时，玩家获得目标装备的概率可能迅速下降：

$$
P(目标) = P(部位) \times P(稀有度) \times P(词缀集合) \times P(数值区间) \times P(组合合法)
$$

这个表达式不是为了制造精确幻觉，而是提醒设计者：每多加一层随机，就会降低玩家命中目标的机会。必须提供定向获取、锁定、重铸、保底或拆解转化，否则玩家只会感到系统在拖时间。

### 4.4 词缀池设计原则

每条词缀至少要满足以下一项：

- 改变战术；
- 改变资源循环；
- 改变技能组合；
- 改变风险与收益；
- 服务一个明确场景。

“对某类敌人增加 1.7% 伤害”不是不能存在，但如果大量词缀都只是这种微小差异，玩家无法感知，也无法形成选择。

## 五、数值区间：让“好”与“能用”分开

随机属性不应只有“垃圾”和“毕业”两个结果。可以把区间划成：

- 可用区：满足基础玩法需求；
- 优质区：适合大多数 Build；
- 极值区：值得收藏或交易；
- 特殊区：与某种组合或场景相关。

设计者需要模拟玩家在不同时间投入下的获得情况：

- 第一次获得目标词缀的时间；
- 获得可用版本的时间；
- 获得优质版本的时间；
- 获得极值版本的时间；
- 从已有装备升级的边际收益。

如果从“可用”到“优质”只提升 2%，却需要 100 小时刷取，系统卖的就不是 Build 深度，而是耐心测试。

## 六、强化系统：失败成本必须可承受

强化系统常见变量包括：

- 成功概率；
- 失败是否降级；
- 是否损坏或归零；
- 保护材料；
- 强化材料来源；
- 强化上限；
- 转移和继承规则；
- 保底触发条件。

### 6.1 期望成本只是最低分析

如果每次尝试成功率为 $p$，且每次独立，首次成功的期望尝试次数是：

$$
E[N] = \frac{1}{p}
$$

但玩家真正关心的还包括：

- 50% 玩家需要多少次；
- 90% 玩家需要多少次；
- 连续失败是否会毁掉已有投入；
- 失败后是否仍能推进；
- 最差成本是否超过玩家心理预算。

所以强化方案必须同时报告期望、分位数和最坏保护，而不是只写一个平均成本。

### 6.2 失败设计的三种方向

#### 可恢复失败

失败消耗材料，但强化进度、保底进度或经验保留。适合强调长期积累。

#### 有限惩罚失败

失败会降级或损失部分投入，但有保护道具和上限。适合制造风险决策。

#### 不可逆重置

失败会大幅清空投入。刺激强，但极易制造后悔和退出，应慎用。

失败不是越痛越有刺激。玩家需要知道损失边界、下一次如何改善，以及是否有不靠再次付费也能恢复的路径。

## 七、套装与散件：设计权衡，不设计唯一答案

套装最常见的问题是：达到两件、四件或六件后，收益直接超过所有散件，导致玩家只有一种正确穿法。

更好的套装设计应让玩家权衡：

| 方案 | 优势 | 代价 |
|---|---|---|
| 散件 | 属性灵活、即时收益 | 缺少组合爆发 |
| 低件数套装 | 容易启动、适配面广 | 上限相对有限 |
| 高件数套装 | 机制独特、上限高 | 放弃其他部位属性 |
| 混搭 | 形成跨套装组合 | 需要更高理解和搭配成本 |

测试套装时不要只测完整毕业配置，还要测：

- 低配能否使用；
- 中途过渡是否合理；
- 不同角色是否有不同价值；
- 套装触发是否和技能、敌人、地图产生意外乘法；
- 玩家是否被迫为了套装放弃所有个性。

## 八、装备评分：不要用一个数字假装理解一切

基础评分可以写成：

$$
Score = \sum_i W_i \times \frac{V_i}{V_{i,max}}
$$

但这里最难的不是求和，而是权重 $W_i$：

- 权重来自哪个场景？
- 是面板权重还是实战权重？
- 是否考虑触发条件和覆盖率？
- 控制、辅助和生存如何换算？
- 低概率高收益是否被均值夸大？

建议将评分拆成：

- 通用评分：便于快速比较；
- 场景评分：副本、PVP、Boss、清杂等；
- 玩法标签：爆发、持续、控制、生存、资源循环；
- 风险提示：需要特定队伍、操作或敌人条件。

评分的职责是帮助玩家做决定，不是替玩家做决定。

## 九、装备经济：掉落、强化和回收必须连起来

装备系统会持续产生物品，因此必须设计出口：

```text
掉落 → 使用/比较 → 强化/重铸 → 替换 → 拆解/交易/收藏
```

没有回收出口时，库存膨胀、界面噪音和货币通胀会一起出现。

回收设计要注意：

- 回收价值不能高到鼓励无限刷取套利；
- 低价值物应能快速处理；
- 已投入强化的装备应有合理继承或返还规则；
- 交易、绑定和拆解状态必须清晰；
- 回收不是单纯销毁，最好与玩家下一步目标有关系。

## 十、验证流程

### 1. 掉落分布模拟

对每个部位、稀有度和词缀组合模拟足够多次，报告：

- 可用装备出现率；
- 目标词缀命中率；
- 优质装备获得时间；
- 重复物比例；
- 无效属性比例；
- 资源回收后的净收益。

### 2. 强化成本模拟

不要只算平均次数。至少输出 P50、P90、P99 成本，并分别模拟有无保底、有无保护和不同活跃度玩家。

### 3. Build 多样性测试

对标准场景和不同玩家水平测试：

- 可行 Build 数量；
- 各 Build 的使用率；
- 最高与中位 Build 的差距；
- 转换 Build 的成本；
- 特殊场景是否存在反直觉强解。

### 4. 版本膨胀测试

每次新增装备都比较：

- 新装备对标准 Build 的提升；
- 新装备对旧装备的替代率；
- 新内容是否只能靠更高数值吸引玩家；
- 旧装备是否还有场景价值；
- 玩家库存和经济是否出现额外压力。

## 十一、常见失败模式

### 垃圾掉落过多

随机层数太多、定向手段太少，玩家主要时间花在清理而非构筑。

### 毕业过快

装备强度差距过大，玩家短时间得到最终答案，后续内容失去追求。

### 毕业过慢

目标概率和强化成本叠乘，玩家永远处于“差一点”，但看不到可规划的路径。

### 无效属性泛滥

属性看似很多，实际上只有少数能影响有效行为。

### 强化惩罚过强

失败清空长期投入，玩家不再尝试风险决策，而是等待最安全的方案。

### 套装强制性过强

一旦套装完成，所有散件、过渡和混搭都失去价值。

### 评分系统误导

玩家跟随评分自动拆解真正适合自己玩法的装备。

## 结语

装备系统的核心不是让玩家永远刷下一件，而是让玩家理解：

- 这件装备为什么值得保留；
- 它适合什么玩法；
- 我为了它放弃了什么；
- 如果没拿到，还有什么替代路径。

随机性提供的是变化，选择才提供深度。装备设计真正要控制的，是随机、投入、回收和决策之间的关系。
