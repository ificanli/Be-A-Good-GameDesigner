# 装备系统设计：从模块预算到掉落、养成与替换

装备系统同时连接角色能力、战利品、构筑和资源经济。设计装备时，不能从“分几个品质、掉率是多少”开始。首先要确定装备在玩家总成长中承担多少能力、多久替换一次、哪些结果是稳定获得的、哪些结果用于长期追求。完成这层规划后，品质、词缀、强化和套装才有共同基准。

本章承接《养成系统规划》。总养成预算决定装备模块的规模，本章继续把预算拆到等级、部位、品质和随机结果，并建立从生成到退出的完整生命周期。

## 1. 明确装备系统的职责

装备可以承担多种职责，但一套系统不宜在没有优先级的情况下全部承担：

- 提供阶段性的基础能力；
- 通过掉落形成战斗后的即时奖励；
- 通过词缀和套装支持构筑选择；
- 通过强化、重铸和制作形成资源消耗；
- 通过稀有外观、收藏或交易提供长期追求；
- 作为内容资格或角色培养的可见证明。

如果装备主要负责稳定成长，关键部位和基础品质就应具有可预期的获取路径。如果装备主要负责随机追求，主线内容不能按高随机完成度标定。如果装备承担构筑选择，各选项需要改变战斗行为，而不只是用不同名称提供相近增伤。

设计前先写一张职责表：

| 职责 | 重要度 | 主要承载层 | 验证指标 |
|---|---:|---|---|
| 阶段成长 |  | 装备等级、基础属性 | 普通玩家完成度、内容门槛 |
| 构筑选择 |  | 词缀、套装、特殊效果 | 有效构筑数量、使用分布 |
| 长期追求 |  | 极值词缀、稀有掉落 | P50/P90 获得周期 |
| 经济消耗 |  | 强化、制作、重铸 | 资源净流量、库存变化 |
| 替换反馈 |  | 品质、等级、外观 | 替换频率、有效掉落率 |

## 2. 从装备模块预算建立模板

设阶段 $s$ 的装备模块应提供属性预算 $G_{gear,s}$。如果装备分为多个部位，部位 $p$ 的权重为 $r_p$，则部位预算初值为：

$$
G_{p,s}=G_{gear,s}\times\frac{r_p}{\sum_j r_j}
$$

权重可以按属性职责分开。例如武器承担较多攻击，防具承担生命和防御；命中、暴击等属性只投放在少数适合玩家理解的部位。若每个部位什么属性都能出现，装备比较会变复杂，词缀池也更容易被无效结果稀释。

模板表至少记录：

| 字段 | 说明 |
|---|---|
| 装备阶段或等级 | 对应的玩家进度和内容 |
| 部位 | 武器、头盔、衣服等 |
| 基础属性 | 稳定提供的能力 |
| 部位权重 | 该部位占装备总预算的比例 |
| 品质系数 | 品质对模板的修正 |
| 随机预算 | 预留给词缀和浮动值的份额 |
| 特殊效果预算 | 套装或机制效果的预留空间 |
| 投放来源 | 哪些玩法、制作或商店产出 |
| 目标获得时间 | 普通玩家首次可用和阶段完成时间 |

基础模板、品质、强化和词缀的结算顺序必须固定。例如：

$$
Attr_{final}=Attr_{template}\times QualityRate\times(1+EnhanceRate)+Attr_{affix}
$$

这只是一种结构。项目也可以让强化只作用于基础属性，或让品质主要增加词缀数量。关键是所有层级共同受装备总预算约束。

## 3. 部位分工与整套价值

部位设计需要同时满足数值分工和掉落体验。权重差异过大时，玩家只关心少数核心部位；权重完全相同则容易失去装备身份。

可以使用以下三种结构：

1. **职责型**：武器负责输出，防具负责生存，饰品负责概率和特殊属性；
2. **均值型**：各部位总价值接近，但属性方向不同；
3. **核心部位型**：少数部位提供大部分能力，其他部位负责构筑和补充。

整套装备价值应重新汇总：

$$
G_{set,s}=\sum_p G_{p,s}
$$

取整、品质和部位缺失可能使最终总值偏离模块预算。表格要同时提供逐件结果和整套校验，不能只确认每件装备公式正确。

如果装备允许双戒指、双手武器或副手互斥，部位权重应按合法穿戴组合计算。单件价值合理，不代表所有组合都合理。

## 4. 装备等级、投放等级和属性等级

三个等级可以不同：

- **装备等级**：玩家看到的物品等级或使用门槛；
- **投放等级**：该装备在哪个玩家阶段开始出现；
- **属性等级**：从哪一阶段的属性模板取值。

分离后，设计者可以让某件稀有装备较早投放但使用稍高的属性模板，也可以让追赶装备显示为当前等级、实际使用较低预算。配置必须明确三者关系，避免策划通过修改显示等级意外改变属性。

装备梯度应设置阶段锚点。玩家能力在新系统、转生或世界等级开启后跳升时，装备模板也应重新分段，不能用单一指数曲线贯穿所有阶段。

## 5. 品质控制什么

品质可以控制基础值、词缀数量、数值区间、特殊效果、外观、交易和回收价值，但不必同时控制所有维度。

| 品质维度 | 主要作用 | 风险 |
|---|---|---|
| 基础属性倍率 | 建立清晰纵向提升 | 低品质必然淘汰 |
| 词缀数量 | 扩大构筑空间 | 随机组合稀释加重 |
| 词缀档位 | 提供极值追求 | 比较成本提高 |
| 独有机制 | 产生玩法变化 | 平衡和制作成本高 |
| 外观与稀有性 | 提供收藏价值 | 与战斗强度可能脱节 |
| 回收价值 | 降低无效掉落损失 | 可能形成刷取套利 |

品质系数不能脱离获得周期讨论。高品质比低品质强 30%，但玩家一小时就能稳定替换，和需要两周才能获得的体验完全不同。

低品质装备若没有过渡、制作材料、外观或特殊词缀价值，最终只会成为自动分解步骤。此时大量品质层级增加的是操作和库存负担，不是选择。

## 6. 定义可用、优质与极值状态

“掉到最高品质”不等于获得目标装备。对一个构筑而言，可分为：

- **不可用**：关键条件缺失；
- **可用**：能够支持构筑正常运行；
- **优质**：相对当前装备有可感知提升；
- **极值**：接近系统允许的最佳组合；
- **特殊用途**：只在特定敌人、队伍或玩法中有效。

设计获得周期时，应分别计算首次可用、优质和极值装备的时间。主线进度通常只依赖可用状态，优质和极值承担优化与长期追求。

状态判定应尽量基于构筑条件和实际表现。例如“至少一个资源循环词缀 + 两个有效输出词缀”比“评分超过 800”更能说明装备为何可用。

## 7. 掉落生成流程与目标概率

先写清生成顺序，再计算概率：

```text
是否掉落装备
→ 装备池或部位
→ 等级与品质
→ 词缀数量
→ 按部位和标签抽取词缀
→ 生成词缀档位与数值
→ 应用互斥、保底或修正规则
```

若各环节独立，目标概率可近似写为：

$$
P(target)=P(slot)P(rarity)P(affixes\mid slot,rarity)P(values\mid affixes)
$$

实际系统中，品质决定词缀数量，部位限制属性，词缀之间还可能互斥，因此通常要使用条件概率、枚举或模拟，不能把界面上的概率机械相乘。

若单次独立掉落命中目标的概率为 $p$，$n$ 次内至少获得一次的概率为：

$$
P(N\le n)=1-(1-p)^n
$$

达到累计概率 $q$ 所需次数为：

$$
n\ge\frac{\ln(1-q)}{\ln(1-p)}
$$

除平均次数外，还应报告 P50、P90 和连续无提升次数。玩家经历的是完整分布，不是长期平均值。

## 8. 词缀池先按功能设计

词缀可按战斗职责分组：

- 直接输出：攻击、技能倍率、暴击等；
- 循环能力：冷却、资源恢复、施法速度；
- 生存方式：生命、减伤、护盾、回复；
- 条件机制：对特定状态、距离或敌人类型生效；
- 操作改变：技能形态、范围、触发或移动方式；
- 场景针对：PVE、PVP、首领或队伍效果。

大量词缀只提供细小的同类增伤，池看似丰富，实际只会降低目标命中率。每个词缀进入池前应说明它支持哪类构筑、在哪些部位出现、是否与其他词缀互斥，以及低值结果是否仍有使用意义。

随机数值可以采用离散档位、均匀分布或中间密集的截断分布。连续数值经过取整后，各离散结果概率会变化，必须按最终显示值重新统计。

## 9. 完整算例：从预算到一件装备

某阶段装备模块满额攻击预算为 600，六个部位的攻击权重如下：

| 部位 | 权重 | 攻击预算 |
|---|---:|---:|
| 武器 | 35 | 210 |
| 项链 | 20 | 120 |
| 戒指 | 15 | 90 |
| 手套 | 15 | 90 |
| 头盔 | 5 | 30 |
| 衣服 | 10 | 60 |
| **合计** | **100** | **600** |

武器的 210 点再拆为：基础模板 150、品质和强化可提供 40、随机词缀期望 20。高品质武器不应在所有层都同时达到上限，否则单件可能越过 210 的规划预算。

假设紫色武器品质系数为 1.1，强化预算上限为基础模板的 10%，词缀期望为 20，则满强化期望攻击为：

$$
150\times1.1\times1.1+20=201.5
$$

剩余约 8.5 点可以作为高词缀结果、特殊效果或取整余量。若品质和强化都误作用于包含词缀的最终值，结果会高于规划。

再估算首次可用武器。若武器占装备掉落的 20%，紫色及以上概率为 10%，可用词缀组合概率为 30%，则单次装备掉落命中可用武器的近似概率为：

$$
0.2\times0.1\times0.3=0.006
$$

即 0.6%。约 115 次装备掉落可达到 50% 累计获得概率，约 383 次达到 90%。若目标是玩家两天内大概率获得，而每天只有 50 次装备掉落，当前规则明显过慢。可以提高定向部位概率、提供制作或保底，而不是只提高全局掉率。

## 10. 强化是装备的一个子模型

强化需要先说明投入绑定在什么对象上：单件装备、部位、角色还是账号。绑定方式决定玩家是否愿意投资过渡装备。

简单强化若失败只消耗材料，单次成功率为 $p$，期望尝试次数为 $1/p$，但仍需查看成本分位数和保底。失败降级、重置或损坏时，才需要状态转移或模拟。复杂算法属于专项计算模型，不应反过来主导整个装备系统。

设计强化时至少记录：

- 每级属性收益及作用基数；
- 材料和货币成本；
- 成功、失败、降级和保底规则；
- 普通玩家到达各节点所需天数；
- 换装时继承、转移或返还比例；
- 保护道具是否形成真实选择。

如果所有理性玩家都会使用保护道具，它就不是选择，而是附加税费。不可逆损失应明确上限，并提供可理解的恢复路径。

## 11. 套装、散件与合法组合

套装强度应相对玩家放弃的散件价值计算：

$$
R_{set}=\frac{Performance_{set}-Performance_{alternative}}{Performance_{alternative}}
$$

评价对象是指定场景中的实际表现，不是属性总和。测试至少覆盖完整套装、过渡件数、散件最优解和跨套混搭。

套装若在所有场景都优于散件，系统已经替玩家完成选择。较健康的结构是让套装提供明确玩法，散件保留属性效率、灵活搭配或场景针对优势。

组合限制必须可见。唯一效果、共享冷却、双手武器互斥和套装冲突不能只藏在结算逻辑里。

## 12. 替换周期与投入继承

装备等级提高不代表每一级都应替换。先规划阶段替换节奏：

| 阶段 | 目标替换部位数 | 主要来源 | 旧装备去向 | 投入继承 |
|---|---:|---|---|---|
| 进入阶段 |  |  |  |  |
| 中段 |  |  |  |  |
| 阶段末 |  |  |  |  |

替换过快时，玩家不会强化或重铸过渡装备；替换过慢时，掉落长期没有意义。继承规则应与替换频率配套：高频替换通常需要部位强化、低成本转移或较高返还；长期装备可以接受更多单件投入。

旧装备的投入可采用：

- 完整转移：降低换装阻力，但削弱新装备的资源消耗；
- 部分继承：保留主要投入，回收一部分成本；
- 部位绑定：强化跟随槽位，不跟随物品；
- 拆解返还：由玩家决定是否退出旧装备；
- 不继承：只适合替换频率低且风险已清楚告知的结构。

不能只看返还比例，还要计算玩家重新达到原强化状态所需的真实天数。

## 13. 评分、比较与自动处理

线性评分可写为：

$$
Score=\sum_i w_i\frac{V_i}{V_{i,max}}
$$

权重依赖职业、构筑和场景，因此全局评分只能粗略筛选。界面最好同时显示基础强度、构筑标签和关键机制，避免玩家按一个数字自动拆解有特殊价值的装备。

自动分解规则应与可用状态一致，而不是只按品质。若低品质可能出现稀有机制或制作价值，系统需要锁定、收藏或二次确认。库存压力不能靠让玩家频繁阅读垃圾装备解决；更有效的办法是减少无效结果、提高批量处理和让回收价值稳定可预期。

## 14. 装备的经济闭环

装备生命周期为：

```text
生成
→ 鉴定与比较
→ 装备、强化、重铸或交易
→ 被替换
→ 拆解、继承、收藏或退出
```

每一步都要记录资源流。拆解返还过高可能形成制作—拆解套利，返还过低会让旧装备成为库存垃圾。随机词缀、重铸材料和强化材料若都来自同一玩法，还要检查玩家是否被单一路径绑架。

建议按周期统计：装备产出数量、有效装备比例、被装备比例、拆解比例、交易比例、强化投入、继承返还和材料净变化。只有掉率没有退出量，装备和材料库存会持续膨胀。

## 15. 验证矩阵

离线验证至少包含：

1. 汇总每阶段整套装备的基础、品质、强化和词缀预算；
2. 枚举或模拟完整生成流程；
3. 计算可用、优质和极值装备的 P50、P90 获得次数；
4. 计算普通玩家各阶段的实际装备完成度；
5. 测试无装备、必得装备、普通完成和高完成玩家；
6. 比较不同职业、构筑和场景的装备收益；
7. 检查强化、转移、拆解和制作的资源净流量；
8. 模拟新阶段开放后的旧装备替代率和投入损失。

上线后观察：各部位替换间隔、有效掉落率、词缀使用率、自动分解率、强化节点分布、库存积压、套装使用集中度和不同构筑的实际表现。

## 16. 常见故障

| 现象 | 优先检查 |
|---|---|
| 装备很多但没有选择 | 词缀功能是否重复，品质是否直接决定一切 |
| 玩家长期刷不到可用装备 | 部位、品质、词缀和数值多层概率相乘 |
| 低品质全是垃圾 | 是否缺少过渡、特殊机制或回收价值 |
| 玩家不强化过渡装备 | 替换周期、继承规则和回本时间 |
| 套装统治所有构筑 | 机会成本、场景边界和散件价值 |
| 新品质上线后旧装备全失效 | 新增预算过大，缺少继承和横向差异 |
| 装备评分误导玩家 | 权重不适用于当前职业或场景 |
| 材料持续膨胀 | 拆解返还、制作消耗和装备退出量 |

## 17. 工作簿结构

建议拆为：

1. 装备职责与阶段预算；
2. 部位权重和属性分工；
3. 等级与品质模板；
4. 词缀池、互斥和数值档位；
5. 掉落生成与来源；
6. 强化、重铸、制作和继承；
7. 套装和合法组合；
8. 掉落概率与获得周期模拟；
9. 装备属性加载和战斗验证；
10. 产出、拆解、交易与材料复盘。

## 18. 发布前检查
