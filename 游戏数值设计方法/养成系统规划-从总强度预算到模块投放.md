# 养成系统规划：从总强度预算到模块投放

项目确定各阶段玩家应达到的能力后，还要决定这些能力由哪些养成系统提供。若等级、装备、强化、技能和天赋分别定数值，它们容易重复投放同一批属性：单个系统看起来合理，合并后的玩家能力却超出内容预算；也可能多个系统消耗相似、收益相似，只是换了界面和材料。

养成规划的主要任务是把阶段能力拆成可解释、可完成、可复盘的模块投放。它要回答：为什么需要这条成长线；它何时开放；提供多少能力；需要投入什么资源和时间；普通玩家在目标日期能完成多少；它与其他养成有什么区别。

## 1. 先确认每条养成线的职责

模块清单只收录会改变玩家长期状态、资源决策或战斗能力的系统。先列清单，是为了避免所有系统都以“变强”为理由存在，却没有独立职责。

| 字段 | 说明 |
|---|---|
| 模块 | 等级、装备、技能、天赋、宠物等 |
| 开放条件 | 等级、任务、自然日或内容进度 |
| 成长对象 | 角色、账号、职业、单件装备或队伍 |
| 主要收益 | 属性、机制、构筑选择或内容资格 |
| 成长方式 | 固定升级、突破、随机获取、收集或赛季重置 |
| 核心资源 | 货币、材料、同名卡、时间或机会次数 |
| 完成周期 | 初次可用、阶段完成和长期毕业所需时间 |
| 重置与继承 | 换装、转职和版本更新时如何处理 |
| 主要职责 | 稳定成长、随机追求、构筑差异或追赶 |

两条养成都增加攻击并不一定重复。等级可以提供稳定基础成长，装备负责阶段替换和构筑选择，天赋负责可重置的方向选择。若两条养成都只是消耗专属材料、点击升级、获得固定全属性，它们的差别主要来自包装，应考虑合并或重新分配职责。

## 2. 从阶段玩家能力得到总预算

养成预算要来自阶段玩家和内容目标，而不是来自系统数量。设阶段 $s$ 的目标攻击为 $Attack_s$，上一阶段为 $Attack_{s-1}$，则该阶段攻击增量为：

$$
\Delta Attack_s=Attack_s-Attack_{s-1}
$$

这个公式用于得到某一阶段需要新增多少攻击。公式后要判断的是：这部分增量哪些必须稳定获得，哪些可以作为选择、随机或高投入差异。生命、防御等属性同理。若属性间存在乘法关系，应先通过战斗模型确定目标结果，再反求输入，不能把所有面板增量简单相加。

阶段预算至少区分六类。必得预算由主流程提供；常规预算由普通活跃玩家预计获得；选择预算由构筑和资源决策决定；随机预算由掉落和词缀形成分布；高投入预算由高活跃或高付费玩家额外获得；临时预算来自活动和场景效果，不进入永久能力。主线一般使用“必得 + 普通常规完成度”标定。若按所有养成满配标定，可选系统会变成必做系统。

统一战力可作为预算筛查：

$$
Power=\sum_i v_i\times a_i
$$

这个公式用于把不同属性汇总成粗略规模，其中 $v_i$ 是属性数量，$a_i$ 是场景权重。公式后不能直接得出实战强弱相等。防御接近阈值时可能很敏感，命中接近上限后边际收益很低，控制和机制效果也难稳定折算。因此战力只做第一层预算，模块最终仍要通过 TTK、生存时间、治疗压力和场景表现验证。

## 3. 把总预算分配给模块

设阶段属性增量为 $\Delta A_s$，分配给模块 $k$ 的权重为 $w_{k,s}$，则：

$$
\Delta A_{k,s}=\Delta A_s\times\frac{w_{k,s}}{\sum_j w_{j,s}}
$$

这个公式用于集中控制模块规模。公式后要检查的是：权重是否符合模块职责和玩家完成度，而不是把权重理解成实战价值天然相等。分配后仍需加载到战斗模型验证。

例如某阶段攻击从 1,000 提高到 1,800：

| 模块 | 满额攻击 | 普通完成度 | 阶段玩家计入 |
|---|---:|---:|---:|
| 等级 | 200 | 100% | 200 |
| 必得装备 | 280 | 90% | 252 |
| 技能被动 | 120 | 80% | 96 |
| 可选天赋 | 80 | 50% | 40 |
| 随机词缀 | 80 | 40% | 32 |
| 社交养成 | 40 | 25% | 10 |
| **合计** | **800** | — | **630** |

满额玩家获得 800 点，普通阶段玩家预计获得 630 点。因此普通内容基准是 1,630，而不是 1,800。剩余 170 点是完成度差异。若主要内容要求接近 1,800，“可选”和“随机”实际上并不可选。

## 4. 根据成长类型决定验证口径

定向成长投入后获得固定结果，例如等级、技能升级和固定强化。它适合承担主要内容门槛，需要记录逐级收益、累计消耗、完成时间和边际性价比。

自由成长允许玩家在多个方向分配预算，例如属性加点和天赋。总量受控，不同分配结果仍会不同。验证时要测试输出优先、生存优先和极端组合。

随机成长通过掉落、抽取或随机词缀获得。普通阶段玩家不能使用理论最大值，应采用可用状态 P50、高完成状态 P90 等分布指标。随机系统承担的能力份额越高，玩家实际差距越难预测。

新增养成线前，也要先判断它属于哪类版本动作：预算内重分配、上限扩展、横向能力、追赶替代或赛季能力。所有新系统都增加永久乘法区是高风险做法。新增 20% 全局攻击会同时放大等级、装备和技能提供的旧攻击，实际增长高于孤立的“新增系统战力”。版本评估必须使用最终战斗结果。

## 5. 继续拆到部位和子系统

模块获得预算后，还要继续拆到能配置的子结构。以装备为例，设装备攻击预算为 $G_{gear,s}$，部位 $p$ 的权重为 $r_p$：

$$
Attack_{p,s}=G_{gear,s}\times\frac{r_p}{\sum r_p}
$$

这个公式用于把装备模块预算分给部位。公式后要判断部位职责：武器可以承担更多输出，防具承担生命和防御；也可以让各部位总价值接近，降低单部位掉落造成的波动。

品质、强化和词缀作用于哪个基数必须明确。例如：

$$
Attr_{gear}=Attr_{template}\times QualityRate\times(1+EnhanceRate)+Attr_{affix}
$$

这个公式用于固定装备子系统的结算顺序。若品质、强化和套装都乘在最终总属性上，组合结果可能远超装备模块预算。规划表要同时显示模板值、各层修正和最终值，不能只看各子系统单独的提升百分比。

## 6. 安排开放时间和首次反馈

新系统开放时，玩家需要理解规则、获得首份资源并看到一次有效成长。短时间连续开放多条养成线，会同时引入新货币、新入口和新决策。

| 时间或等级 | 开放模块 | 首次可用 | 首次明显提升 | 稳定循环形成 | 对应内容 |
|---|---|---:|---:|---:|---|
|  |  |  |  |  |  |

“开放”不等于“可用”。入口出现后两天才能获得首个节点，反馈会很弱；开放瞬间送满早期资源，又会跳过学习过程。通常应先让玩家获得并理解成长，再在后续内容中验证。若同一关既开放系统又要求依赖它通关，成长更像钥匙税。

## 7. 对齐收益、消耗和完成时间

每条养成线至少包含累计收益和累计消耗两条曲线。第 $n$ 级的边际性价比为：

$$
Efficiency_n=\frac{Gain_n-Gain_{n-1}}{Cost_n-Cost_{n-1}}
$$

这个公式用于判断某一级投入是否值得。公式后要检查的是节点作用：前期高性价比可帮助玩家建立习惯；中期稳定形成常规消耗；突破节点收益跳升会促使玩家囤积；后期边际下降可承担长期消耗，但不适合成为主线硬门槛。

成本不只是货币，还包括获取天数、玩法次数、失败风险和放弃其他养成的机会成本。最简完成时间为 $Days=C/R$，其中 $C$ 为累计消耗，$R$ 为每日可得资源。实际模型还要加入开放时间、参与率、随机掉落和资源分流。同一资源被多个系统竞争时，不能给每个系统都使用完整日产量。

## 8. 完整算例：四周阶段预算如何落到模块

下面使用一个虚构阶段说明预算分配。例子只展示方法，不代表推荐比例。

**规则。** 阶段入口攻击为 1,000，四周后普通玩家目标为 1,600，高完成上限为 1,800。各模块满额、完成度和资源如下：

| 模块 | 满额增量 | 四周普通完成度 | 普通增量 | 主要资源 |
|---|---:|---:|---:|---|
| 等级 | 160 | 100% | 160 | 经验 |
| 装备替换 | 280 | 80% | 224 | 掉落、制作材料 |
| 技能升级 | 160 | 75% | 120 | 技能书、金币 |
| 天赋选择 | 120 | 50% | 60 | 天赋点 |
| 随机词缀 | 80 | 45% | 36 | 掉落、重铸材料 |
| **合计** | **800** | — | **600** | — |

**玩家状态。** 等级贯穿四周；装备第一周开放并持续替换；技能第二天开放，形成稳定消耗；天赋第二周开放，形成选择；随机词缀在基础装备学习完成后开放。

**结果。** 普通玩家四周后获得 600 攻击增量，达到 1,600；高完成玩家最多获得 800 增量，达到 1,800。若资源模型算出普通玩家四周只能完成技能预算的 55%，而非目标的 75%，可以提高技能书产出、降低消耗、下调技能完成度并把能力转给其他模块，或接受普通玩家能力低于 1,600 并重做内容。

**判断。** 不能只提高技能单级属性，因为这会同时抬高满额上限。还要把不同消费策略加载到战斗模型：若输出优先玩家第三周达到 1,650，均衡玩家只有 1,480，主线按哪类玩家标定必须明确。挑战内容可以鼓励优化，主线通常不应把一种资源策略变成唯一答案。

## 9. 用成长复盘验证真实完成度

成长复盘按日模拟资源和养成选择：

```text
每日玩法产出
→ 资源库存
→ 判断可升级节点
→ 按策略选择养成
→ 扣除资源
→ 更新模块完成度
→ 汇总玩家属性
→ 验证可通过内容
```

至少建立均衡、输出优先、生存优先和囤积突破四种策略。机制解锁、外观、红点和阶段奖励都会改变玩家选择，不能只按理论性价比自动消费。复盘输出应包含各日模块等级、库存、已投入资源、阶段玩家属性、可通过内容和距离下个节点的时间。这样才能判断问题来自资源不足、消费策略还是模块收益。

常见故障可以先按变量定位：

| 现象 | 优先检查 |
|---|---|
| 系统很多但感觉一样 | 模块职责、操作和收益类型是否重复 |
| 普通玩家低于内容门槛 | 完成度假设、产出和可选预算是否被当成必得 |
| 某系统成为唯一投入答案 | 边际性价比、乘法位置和突破奖励 |
| 玩家囤资源不升级 | 即时收益、替换风险和未来节点性价比 |
| 新系统上线后旧内容崩溃 | 是否新增总预算或永久乘法区 |
| 显示战力接近但实战差距大 | 战力权重、属性阈值和场景效果 |
| 模块延期导致全局失衡 | 内容是否按包含该模块的玩家标定 |
| 资源永远不足或大量积压 | 产出、消耗、分流和完成周期 |

调整时先确认问题属于总预算、模块分配、完成度、资源还是战斗换算。直接修改某个系统的最终属性，常会掩盖上游错误。

## 10. 工作簿结构

建议拆为：

1. **模块清单**：职责、开放、资源和继承；
2. **阶段总预算**：目标玩家和属性增量；
3. **模块分配**：满额预算、普通完成度和高投入上限；
4. **子系统配置**：部位、品质、等级和节点；
5. **消耗产出**：累计成本、日产量和资源竞争；
6. **成长复盘**：按日模拟库存、选择和完成度；
7. **属性加载**：合并模块并进入战斗模型；
8. **检查页**：预算超额、完成时间、异常性价比和内容门槛。

输入参数、生成配置和验证输出应分开。人工修正要有独立字段和原因，避免公式结果被静默覆盖。

## 11. 发布前检查

- [ ] 每条养成线是否有独立职责，而非换皮升级？
- [ ] 总预算是否来自阶段玩家和内容目标？
- [ ] 是否区分满额、普通完成度和随机分布？
- [ ] 模块预算是否继续拆到部位、品质和子系统？
- [ ] 开放、首次可用和形成循环是否分别记录？
- [ ] 收益、消耗、产出和完成时间是否闭环？
- [ ] 是否模拟多种资源消费策略？
- [ ] 战力预算是否经过完整战斗模型验证？
- [ ] 新系统属于重分配、扩展、横向、追赶还是赛季能力？
- [ ] 模块延期或删除时，能否快速找到受影响内容？
