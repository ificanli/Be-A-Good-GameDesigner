# 数值工作簿设计：输入、计算、输出与检查

当一个数值工作簿进入多人维护阶段，最危险的不是公式复杂，而是参数、公式、配置和检查混在一起。策划改了一个倍率，程序不知道导出的配置是否仍与服务器 Schema 对齐，评审者也无法判断异常来自输入、引用、取整还是人工覆盖。

```text
Inputs → Calculations → Outputs → Checks
```

## 1. 先建立工作簿总入口

在 `00_README` 说明工作簿用途、输入区、生成步骤、依赖文件、更新时间和发布状态。发布状态至少区分草稿、评审和发布版本。若工作簿需要人工覆盖，先在总入口说明覆盖记录页的位置，不要把覆盖值散落在公式区。

总入口还要列出生成顺序。评审者应能从这里知道先改哪些输入，哪些页只读，哪些输出会进入配置发布。若没有这个入口，大表拆分只会把一个难查的文件变成多个难查的文件。

## 2. 建参数字典，再录入系统输入

在 `01_参数字典` 为每个参数记录字段：ID、名称、类型、单位、默认值、范围、所属系统、来源、负责人和版本。概率、百分比、万分比、秒和毫秒必须写在字段中，不能只靠列名或颜色猜测。

录入系统输入时，先区分三类对象：设计输入、外部引用和计算结果。设计输入允许策划调整。外部引用只读取公共基准或其他系统输出。计算结果只由公式生成。颜色可以辅助识别，但颜色不能作为唯一语义。

公共基准放在 `02_公共基准`，并只维护一份。具体系统表通过稳定 ID 读取公共基准，不复制一份再手改。若删除或插入行后引用会改变，就把引用改成 ID 引用，再继续录入。

## 3. 固定计算层的引用方向

在 `20_中间计算` 放公式和中间结果，不在输入页堆公式，也不在输出页临时补公式。引用方向保持单向：输入和公共基准进入计算层，计算层进入输出层，检查层读取前面各层。不要让检查项反写输入，也不要让输出页反向参与公式计算。

跨表引用必须使用稳定 ID。若工作簿需要跨文件读取，先画出依赖图，再评估修改会传播到哪些输出。依赖图不需要复杂，只要能回答一个问题：改动某个参数后，哪些配置和图表必须重新生成。

人工覆盖单独记录值、原因、负责人和版本。覆盖值不能藏在公式中，否则排错时无法分辨是公式错误、输入错误还是人工决策。

## 4. 生成配置输出

在 `30_配置输出` 对齐服务器 Schema。输出表必须检查必填、唯一键、枚举、范围和引用。若服务器字段名、字段类型或枚举值改变，先更新输出结构，再生成配置。

明确哪一侧是权威。不要让程序把策划表中的公式再实现一遍，除非团队已经规定程序计算结果才是权威。无论权威在哪一侧，都用 `40_黄金样例` 对账：给出一组固定输入、期望中间结果和期望输出，用来发现公式重写、取整和单位换算带来的差异。

生成过程必须可重复执行。同一版本输入应得到相同输出。导出文件附带版本、时间和校验值，便于发布后确认线上配置来自哪次生成。

## 5. 用图表看生产风险

在输出可用后再做图表。图表用于观察曲线、阶段跳点、分布和版本差异，不用于替代检查项。

不要只画平滑总曲线。经验、金币、掉落、成长和战力类数据还要显示逐级时间、累计投入、分位数和异常点。每张图表标明单位、玩家层和配置版本，否则评审者无法判断曲线变化来自玩家分层、单位换算还是版本差异。

## 6. 加自动检查并设发布门禁

在 `50_边界检查` 放自动检查。至少包含概率归一、ID 引用、负值、上限、分段连接、预算总和、产销缺口、资产对账和旧版差异。错误输出指向具体行、字段和规则，不要求评审者肉眼扫描整张表。

关键检查必须给出明确 PASS 或 FAIL。若某项检查只是提示风险，也要写清它不会阻断发布。生产门禁不能只靠“看起来没问题”。

## 7. 拆大表，但保留统一入口

当结构庞大时，将参数、生成数据和查询工具分开。推荐目录如下：

```text
00_README
01_参数字典
02_公共基准
10_系统输入
20_中间计算
30_配置输出
40_黄金样例
50_边界检查
60_版本差异
```

查询页允许输入等级、品质、角色或版本，并返回关键结果，避免团队在几千行数据中手动查找。拆表后仍要保留总入口、依赖和生成顺序。文件越多不代表模块化越好，跨文件引用失控同样危险。

`60_版本差异` 不只列单元格变化。它应把变化转成 TTK、完成时间、资源总量、掉落期望或其他业务指标，让评审者知道一次参数修改改变了什么体验结果。

## 8. 交接和故障定位

工作簿交接时，附上黄金样例、已知限制、手工步骤和故障恢复方式。只交一个能运行但没人敢改的文件，等于没有完成生产交接。

结果异常时，按顺序定位：先检查输入版本，再检查引用和单位，然后检查公式与取整，最后检查人工覆盖。若工作簿无法指出某个结果来自哪些参数，就补充公式追踪或中间输出，不要继续在结果页猜原因。

## 发布前检查

- [ ] 输入、计算、输出和检查是否分层？
- [ ] 参数是否有类型、单位和范围？
- [ ] 公共基准是否集中维护？
- [ ] 配置能否自动校验和重复生成？
- [ ] 新旧版本能否查看语义差异？
