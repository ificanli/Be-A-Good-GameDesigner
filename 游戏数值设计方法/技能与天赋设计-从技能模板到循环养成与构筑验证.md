# 技能与天赋设计：从技能模板到循环、养成与构筑验证

技能决定玩家在战斗中能做什么，天赋和修改器决定这些行动如何变化。技能数值不能只比较单次伤害；同样的面板倍率，在动作时间、命中条件、冷却、资源和目标数量不同的情况下，实际价值会明显不同。

本章从角色战斗职责和养成预算出发，建立单技能模板，再扩展到技能循环、升级消耗、天赋结构和完整构筑验证。伤害结算层和 TTK 的通用计算见战斗设计专题。

## 1. 先定义角色的战斗职责

技能列表应从角色或流派需要完成的行为开始，而不是先凑齐固定数量的主动技能。设计者需要说明：

- 角色如何进行常规输出；
- 如何获得和消耗战斗资源；
- 如何接近、脱离或调整位置；
- 如何处理群体、单体和高压目标；
- 如何防御、恢复或创造安全窗口；
- 队伍中承担什么职责；
- 失误后如何恢复循环；
- 与其他角色或流派相比，主要优势和代价是什么。

可以先建立行为槽位：填充、生成、消耗、爆发、防御、位移、控制和团队功能。槽位不是强制每类一个技能，而是检查角色是否缺少完成核心职责的手段。

如果两个技能都只是在冷却结束后造成相近范围伤害，它们很可能争夺同一行为位置。动画、元素类型和名称不同，并不能证明决策不同。

## 2. 技能模板要记录完整成本

每个技能至少记录：

| 类别 | 字段 |
|---|---|
| 身份 | 技能 ID、名称、类型、标签、所属流派 |
| 使用条件 | 目标、距离、姿态、武器、资源和前置状态 |
| 动作 | 前摇、持续、后摇、取消窗口、移动和霸体 |
| 伤害或治疗 | 基础值、属性系数、段数、伤害类型、快照规则 |
| 范围 | 形状、尺寸、目标数、选取与衰减 |
| 冷却 | 基础冷却、充能、共享冷却和重置 |
| 资源 | 消耗、生成、上限、溢出和返还 |
| 状态 | Buff、Debuff、层数、持续时间和刷新方式 |
| 风险 | 被打断、位置暴露、未命中损失和机会成本 |
| 成长 | 开放时间、等级、升级收益和消耗 |
| 接口 | 可被哪些天赋、装备、队友和敌人规则修改 |

技能说明中的“造成 300% 攻击伤害”只覆盖了一个字段。若表里没有动作和资源，无法判断它是否比 200% 伤害的快速技能更强。

## 3. 单次期望效果

伤害技能的简化期望值可写为：

$$
E[D_i]=(Base_i+k_i\times Attack)\times HitRate_i\times TargetFactor_i\times Condition_i
$$

其中 $TargetFactor_i$ 表示目标数量、群体衰减和实际覆盖；$Condition_i$ 表示背击、标记或其他条件的平均实现比例。公式只用于同一场景下的初步比较，最终伤害仍按完整结算流程计算。

按动作时间计算的单次效率为：

$$
ActionEfficiency_i=\frac{E[D_i]}{CastTime_i+Recovery_i}
$$

该指标回答“技能占用一秒行动时间能产生多少效果”，不包含冷却和长期资源。高倍率技能如果动作过长，可能降低输出窗口内的总效果；低倍率技能如果承担资源生成，其价值也不能只用伤害表示。

控制、位移和无敌没有脱离场景的固定伤害换算。应在具体场景中比较它改变了多少可输出时间、规避了多少伤害、打断了什么敌方行为，或提高了多少成功率。

## 4. 目标数量不能直接当倍率

一个可命中五个目标的技能，不等于稳定获得五倍价值。有效目标数受敌人密度、站位、范围、锁定和存活时间影响。

可以定义场景中的平均有效目标数：

$$
N_{effective}=\sum_{n=1}^{N_{max}}n\times P(N=n)
$$

若技能对后续目标有衰减，还需逐目标计算。技能模板应分别记录理论上限和标准场景下的有效目标数。单体首领、三目标小队和密集怪群需要不同基准，不能用一个“平均目标数”解释所有内容。

## 5. 从单技能进入动作循环

完整循环应从一个可重复状态开始，到资源、冷却和关键状态再次回到相同状态结束：

$$
DPS_{rotation}=\frac{\sum_i E[D_i]N_i}{T_{rotation}}
$$

$N_i$ 是循环内使用次数。时间轴需逐步更新：

```text
初始资源与冷却
→ 使用技能并占用动作时间
→ 结算资源和状态
→ 推进所有冷却与持续时间
→ 选择下一个合法行动
→ 回到可重复状态
```

若循环无法回到初始状态，例如资源持续下降或增益逐层累积，就要扩大观察窗口，区分开场爆发、稳定循环和枯竭阶段。

## 6. 冷却、动作和使用次数

固定窗口 $T$ 内，技能理论使用次数不能只用 $T/CD$。首发时点、动作时间、充能和战斗结束边界都会影响结果。

如果技能在 $t_0$ 首次可用，冷却为 $C$，不考虑动作冲突，完整释放次数为：

$$
N=\begin{cases}
0,&T<t_0\\
1+\left\lfloor\frac{T-t_0}{C}\right\rfloor,&T\ge t_0
\end{cases}
$$

多个技能共享同一角色动作时间时，还要扣除冲突。青云诀项目表使用“总循环时长减去其他技能动作占用，再计算普攻填充”的结构，这比直接把各技能次数相加更接近实际战斗。

冷却缩减常见两种定义：

$$
C_{final}=C_0(1-r)
$$

或将属性定义为急速：

$$
C_{final}=\frac{C_0}{1+h}
$$

前者接近 100% 时频率急剧增加，后者使施放频率随 $h$ 线性增长。选择哪种都要重新计算资源、状态覆盖和触发链，不能只改技能说明中的秒数。

## 7. 资源系统形成节奏

稳定循环的资源变化可写为：

$$
\Delta R=Generation+Recovery-Spending-Overflow
$$

长期净变化持续为负，循环最终枯竭；长期大量溢出，资源生成属性失去价值。短期爆发可以消耗储备，但要定义恢复阶段及恢复阶段仍可进行的行动。

资源设计应回答：

- 哪些行动生成和消耗资源；
- 玩家如何预判资源不足；
- 未命中、被打断和目标死亡是否返还；
- 资源上限是否制造储备决策；
- 枯竭后需要多久恢复；
- 多余资源能否转换为其他收益。

若管理失败只导致停手等待，系统增加的是空窗而非决策。较好的恢复状态通常仍允许玩家使用低收益行动重新建立循环。

## 8. 状态、连携与触发接口

一个技能施加标记，另一个技能消耗标记，是最常见的连携。接口必须记录：

- 状态由谁施加，持续多久；
- 是否叠层，最大层数是多少；
- 消耗、刷新和覆盖顺序；
- 采用施加时快照还是触发时实时属性；
- 哪些技能、装备和队友效果可以读取；
- 触发效果是否能够再次触发同类效果；
- 每帧、每目标和每次施法的触发上限。

没有递归深度、共享冷却或触发次数限制时，技能、装备和天赋组合可能形成无限循环。限制应写入接口规范，而不是出问题后补特殊判断。

Buff、秘籍、符文等技能修改器也使用同一接口。修改器可以改变倍率、范围、资源、目标选择或技能用途，但每次改变都要重新验证动作循环和触发图。

## 9. 技能升级属于养成模块

技能等级应从技能养成预算中获得收益，而不是每级随意增加固定倍率。先确定阶段满额、普通完成度和开放时间，再分配给技能。

技能升级收益可以分为：

- 数值成长：伤害、治疗、护盾和持续时间；
- 循环成长：冷却、资源消耗和充能；
- 功能节点：新目标、新状态或新连携；
- 专精分支：改变用途并形成选择。

每级边际性价比为：

$$
Efficiency_n=\frac{Effect_n-Effect_{n-1}}{Cost_n-Cost_{n-1}}
$$

其中效果应在标准循环中计算，而不是只看面板倍率。降低 1 秒冷却可能让技能在 20 秒窗口内多用一次，其收益会产生离散跳点。

若升级需要两种资源，完成时间由更慢的一项决定：

$$
Days_n=\max\left(\frac{Cost_{A,n}}{DailyA},\frac{Cost_{B,n}}{DailyB}\right)
$$

共享货币还要考虑其他技能和系统竞争。所有技能都按完整日产量估算，会低估总培养周期。

## 10. 完整算例：生成、消耗与填充循环

假设角色拥有以下技能：

| 技能 | 期望伤害 | 动作时间 | 冷却 | 资源变化 |
|---|---:|---:|---:|---:|
| 普攻 | 100 | 1.0 秒 | 无 | +20 |
| 生成技 | 240 | 1.2 秒 | 6 秒 | +40 |
| 消耗技 | 700 | 1.5 秒 | 无 | -100 |
| 爆发技 | 900 | 2.0 秒 | 12 秒 | 0 |

初始资源为 0，资源上限 100。一个稳定片段可以是：生成技、三次普攻、消耗技。总时间为 5.7 秒，资源正好达到 100 后消耗，伤害为：

$$
240+3\times100+700=1,240
$$

该片段平均 DPS 约为 217.5。爆发技冷却结束时还要插入循环，它占用 2 秒，可能推迟生成技和资源消耗。不能简单把 $900/12=75$ 加到前述 DPS 上，因为动作时间发生竞争。

若某天赋让生成技资源从 40 提高到 60，循环可能减少一次普攻：生成技、两次普攻、消耗技，总时间 4.7 秒，伤害 1,140，DPS 约 242.6。天赋的价值来自改变行动序列，不只是“多生成 20 资源”。

如果另一项天赋只让资源提高到 50，仍需要三次普攻才能达到 100，它在该循环中可能没有即时收益，只减少了未命中或资源损失后的恢复压力。离散阈值必须通过时间轴识别。

## 11. 天赋节点的职责

天赋节点可以分为：

1. **数值强化**：提高已有行动效率；
2. **功能转换**：改变伤害类型、资源来源或技能用途；
3. **行为解锁**：增加行动或连携；
4. **约束交换**：牺牲一项能力换取另一项专精；
5. **容错调整**：降低操作要求，但不一定提高理论上限。

小幅数值节点可以平滑成长，但不能承担主要选择。若节点在所有场景都提高收益且没有机会成本，它更像基础能力的延迟发放。若所有构筑必点，应考虑将其并入角色基础套件。

一条路线只有点满后才能运行时，中途节点需要提供过渡价值。否则玩家成长期间使用的是残缺构筑，重置成本又会阻止试错。

## 12. 天赋树结构与点数约束

常见结构包括：

- 线性路线：理解简单，但选择较少；
- 分叉树：通过前置形成专精，容易出现路径税；
- 层级选一：每层做一次清晰选择，组合数量可控；
- 技能独立修改器：直接围绕单技能变化，容易理解；
- 标签网络：跨技能建立协同，组合空间大但验证成本高。

结构应由选择目标决定，不是树越大越有深度。点数总量、前置成本、重置规则和解锁时间共同决定实际可选空间。

路径税是为了到达目标节点而被迫购买无关节点。少量路径成本可以控制强力组合，但如果大量点数没有实际价值，玩家会把树理解为伪装的等级门槛。

重置成本决定玩家是否敢尝试。内容频繁要求切换构筑时，永久或高额重置成本会惩罚适应玩法；如果希望角色身份稳定，可以限制战斗内切换，而不必让长期重置不可承受。

## 13. 构筑不是节点组合数量

构筑至少应满足三层：

- **可用**：能够完成基础内容并维持循环；
- **有竞争力**：在目标场景接近主流方案；
- **有区别**：行动、风险、资源或团队职责确实不同。

可以建立“构筑—场景”矩阵：

| 构筑 | 单体短战 | 单体长战 | 群体 | 高移动 | 生存压力 | 操作难度 |
|---|---:|---:|---:|---:|---:|---:|
|  |  |  |  |  |  |  |

若一个构筑所有列都占优，它更接近全局最优解；不同构筑在不同列有优势，才可能形成有效专长。

高使用率不必然代表过强，也可能来自操作简单、装备易得、默认推荐或攻略传播。需要联合观察使用率、结果、熟练度、获取成本和场景。

## 14. 操作难度和容错收益

高难构筑不一定必须拥有更高理论上限，但其成本必须有对应收益，例如更强爆发、更高机动或更好的场景适应。验证时至少模拟：

- 理想操作；
- 普通延迟和少量失误；
- 关键技能未命中；
- 资源溢出或枯竭；
- 目标移动和阶段切换。

可以比较理论值和普通玩家值之间的保留率：

$$
Retention=\frac{Performance_{normal}}{Performance_{ideal}}
$$

两个构筑理论 DPS 接近，但一个保留率 90%，另一个 60%，实战分布会明显不同。界面和推荐系统也应反映操作要求。

## 15. PVE、PVP 与团队场景

同一技能在不同场景中的价值可能完全不同。长控制对普通怪很强，对首领可能无效；位移在木桩模型中没有伤害，却可能显著提高实战输出时间；团队增益的价值取决于人数和队友输出。

不建议用一套固定“控制等于多少伤害”覆盖所有场景。可以分别建立：

- PVE 单体与群体循环；
- 首领机制和阶段窗口；
- PVP 双方行动与控制链；
- 团队增益的受益人数和覆盖率；
- 自动战斗的技能优先级与目标选择。

若 PVE/PVP 使用不同参数，配置和描述必须能追溯差异，避免玩家面对隐蔽修正。

## 16. 验证与回归

每个角色或流派至少保留：

1. 无天赋基础循环；
2. 官方推荐构筑；
3. 输出、生存和功能向构筑；
4. 最高冷却和最高资源生成极端构筑；
5. 关键触发递归组合；
6. 低操作与高操作模拟；
7. PVE、PVP 和团队标准场景；
8. 成长过程中的未毕业构筑。

版本调整后，不只比较最终 DPS，还要比较资源曲线、技能次数、增益覆盖、空窗、爆发时点和失败恢复。两个版本最终伤害相同，行动节奏也可能已经完全改变。

上线指标包括技能使用率、命中率、取消率、资源溢出、循环中断位置、天赋选择率、重置率、构筑表现分布和不同熟练度玩家的结果。

## 17. 常见故障

| 现象 | 优先检查 |
|---|---|
| 技能看似很多但按法固定 | 行为职责是否重复，资源和状态是否形成选择 |
| 某天赋必点 | 是否无条件增益、机会成本过低或本应属于基础套件 |
| 纸面构筑无法运行 | 资源、冷却、动作时间或关键装备条件 |
| 高资源生成没有收益 | 是否仍未跨过行动次数阈值，或长期溢出 |
| 自动战斗远弱于手动 | AI 优先级、目标选择和资源规则 |
| PVP 出现无限控制 | 冷却、递减、免疫和触发递归 |
| 技能升级没人投入 | 边际性价比、替代资源用途和功能节点 |
| 天赋树很大但选择很少 | 路径税、前置、必点和无效节点 |

## 18. 工作簿结构

建议拆为：

1. 角色职责与行为槽位；
2. 技能基础模板；
3. 伤害、治疗和状态参数；
4. 动作、冷却、资源和目标规则；
5. 技能升级收益与消耗；
6. 天赋、修改器和触发接口；
7. 单技能比较和循环时间线；
8. 构筑—场景验证矩阵；
9. PVE/PVP/团队回归；
10. 上线指标与版本差异。

## 19. 发布前检查

- [ ] 技能是否对应明确战斗职责？
- [ ] 模板是否包含动作、冷却、资源、目标和风险？
- [ ] 群体技能是否使用实际有效目标数？
- [ ] 循环是否处理动作冲突和离散使用次数？
- [ ] 资源枯竭后是否仍有可玩的恢复行动？
- [ ] 状态和触发是否有快照、优先级和递归限制？
- [ ] 技能升级是否接入养成预算和完成时间？
- [ ] 天赋是否产生机会成本和行为变化？
- [ ] 是否测试未毕业、普通操作和极端组合？
- [ ] PVE、PVP 和团队规则是否分别验证？

## 来源与核验说明

- 青云诀《能力框架.xlsx》中的人物技能基础工作表：技能系数、固定伤害、目标数、冷却、动作时间、使用次数和开放时间的表结构；
- 明澈流风《游戏数值建模 V1.0》：流派载体、技能参数、Buff、技能修改器、升级消耗和 PVE/PVP 模拟；
- 《游戏数值策划完全教程》第 4 章：冷却、资源循环、连携、天赋树和构筑验证主题；
- 本库《养成系统规划》《伤害流程设计》《输出循环与 TTK》：技能预算、结算口径和时间线验证。

项目资料中的具体技能倍率、开放等级、资源产量和升级参数没有作为通用值。原教程涉及的商业游戏案例也未作为无需版本核验的证据。
