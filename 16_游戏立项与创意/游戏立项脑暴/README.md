# 游戏立项脑暴：从创意生成到原型决策

## 系列定位

本系列研究一个游戏想法如何从模糊兴趣，逐步变成可以讨论、验证、淘汰或正式立项的设计方案。

这里的“脑暴”不等于无限罗列点子。完整过程包含四类工作：

1. 建立约束，明确要解决的产品问题；
2. 生成能改变玩家判断的机制候选；
3. 通过查重、纸面推演和范围评估淘汰弱方案；
4. 用最小原型取得证据，再决定继续、返工或停止。

系列重点讨论以下问题：

- 创意从哪里来，怎样避免只换题材；
- 两种成熟玩法怎样融合，才不是前后拼接；
- 怎样判断微创新是否进入高频操作；
- 如何在写完整策划案之前做查重和反证；
- 怎样模拟前 30 秒、前三分钟和完整单局；
- 原型究竟应该验证什么；
- 为什么“系统完整”不等于“核心好玩”；
- 如何把试玩反馈转化为立项证据；
- 什么时候应该继续，什么时候应该放弃。

## 参考项目

系列主要参考两个本地项目目录：

```text
E:/NewGame
E:/NewGame-prototypes
```

前者保存脑暴记录、候选设计、淘汰理由、制作流程与验收报告；后者保存多个实际可玩的 HTML 原型。二者共同提供从想法到原型反馈的完整过程证据。

重点案例包括：

- 《弹射梭哈／五球满贯》：台球弹射、组合构筑与继续冒险；
- 《贪吃蛇军火库》：蛇身作为武器加工流水线；
- 《叠层矿场》：叠层取牌与实体生产经营；
- 《扫雷占城》：扫雷开图与领土扩张；
- 《坠楼消除》：三消破坏支撑与建筑坠落。

案例不会被写成成功宣传。设计稿、实际实现和试玩反馈不一致的地方，恰恰是本系列最有价值的部分。

## 内容结构

### 第一章：立项问题与创意生成

- 00 · 立项不是先想玩法：先定义约束、目标与证据
- 01 · 创意的六种入口：替换、提升、删除、重写、玩具与张力
- 02 · 从成熟母体出发：识别高频操作与可替换环节

### 第二章：机制筛选与方案成形

- 03 · 机制创新的判断：操作、信息、局面与学习
- 04 · 玩法融合：一次输入怎样同时服务两个系统
- 05 · 候选查重：相似产品、核心差异与原创性边界
- 06 · 纸面推演：前 30 秒、前三分钟与完整单局
- 07 · 风险、范围与商业接口：在写代码前排除伪需求

### 第三章：原型验证与试玩诊断

- 08 · 最小原型：只实现最危险的设计假设
- 09 · 从灰盒到完整局：教学、压力、高潮与结算
- 10 · 试玩观察：区分理解问题、实现问题与核心循环问题
- 11 · 迭代与止损：继续、返工、降级或淘汰

### 第四章：立项决策

- 12 · 立项评审：用证据冻结核心、范围与下一阶段目标

## 案例使用方式

五个案例不会各写一篇流水账。每篇方法文会引用适合的问题：

| 方法问题 | 主要案例 |

| 高频操作与微创新 | 弹射梭哈、扫雷占城 |
| 两套系统是否真正耦合 | 叠层矿场、坠楼消除 |
| 信息负荷与教学顺序 | 叠层矿场、贪吃蛇军火库 |
| 原型与设计稿偏差 | 弹射梭哈、扫雷占城 |
| 核心爽点是否成立 | 弹射梭哈 |
| 玩家不理解机制时如何诊断 | 坠楼消除 |
| 原型好玩但产品尚不完整 | 弹射梭哈、叠层矿场 |
