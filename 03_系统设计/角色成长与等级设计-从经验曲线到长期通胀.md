# 角色成长设计：经验曲线、累计投入与追赶机制

角色成长系统安排玩家在多长时间内获得哪些能力。等级、经验和属性是这一过程的表示方法，不能代替对游玩时间、内容消耗速度和能力解锁顺序的设计。

## 1. 从升级时间反推经验需求

设玩家在等级 $n$ 时的单位时间经验产出为 $R_n$，设计目标是该等级平均经过 $T_n$ 小时升级，则该级经验需求可先估为：

$$
EXP_n=R_n\times T_n
$$

这一关系比先选线性或指数公式更有用，因为玩家直接感受到的是升级时间。$R_n$ 需要根据实际行为估计，包括任务、战斗、探索、失败和等待；不能只采用最高效率路线。

完成各等级的目标时间表后，再用曲线拟合或分段函数减少配置量。常见形式包括：

- 线性：$EXP_n=a+bn$，适合稳定增加升级时间；
- 多项式：$EXP_n=an^p+b$，适合逐渐提高后期成本；
- 指数：$EXP_n=ar^n$，适合跨数量级增长，但对参数和追赶机制要求较高；
- 分段函数：不同阶段采用不同增速，用于配合教程、内容开放和长期目标。

曲线名称不代表体验。两个公式只要在玩家经历的等级区间内给出近似数值，实际体验就可能相同。应比较每级时间、累计时间和内容解锁，而不是只比较函数外形。

## 2. 检查累计投入

达到等级 $L$ 的累计经验为：

$$
C(L)=\sum_{n=1}^{L-1}EXP_n
$$

累计量用于判断玩家资产、追赶成本和版本迁移。等级编号只说明玩家位于哪一段，不能说明已经投入多少时间。若改版后经验曲线发生变化，直接按等级一一映射可能造成投入损失。

较稳妥的迁移方法是先把旧等级转换为累计投入，再在新曲线上寻找满足 $C_{new}(L')\le C_{old}$ 的最高等级，并将差额保留为当前级经验。若旧系统还有材料、解锁或付费资产，必须分别建立映射，不能把所有投入压成一个等级数。

## 3. 经验来源决定玩家行为

总经验产出应拆到具体活动：

$$
R_n=\sum_j Frequency_j\times Reward_{j,n}\times CompletionRate_j
$$

$Frequency_j$ 是活动频率，$Reward_{j,n}$ 是等级 $n$ 时的单次奖励，$CompletionRate_j$ 是完成率。设计者需要分别模拟主线玩家、探索玩家、重复刷取玩家和低活跃玩家。

当某项活动的单位时间经验显著高于其他活动时，经验系统会把它变成事实上的必做内容。若希望玩家保有路线选择，应比较不同路线在一段时间内的累计收益，而不是只保证每个活动“都有奖励”。日常上限可以控制产出，但也可能把游玩转化为打卡义务，应同时检查错过后的恢复途径。

## 4. 属性成长与结算层级

等级成长通常同时影响基础属性、装备可用范围、技能等级和内容准入。属性结算需要书面规定层级，例如：

```text
基础属性
→ 固定加成
→ 百分比加成
→ 条件加成
→ 场景修正
→ 上限或软上限
→ 取整
```

每层必须说明加法或乘法关系、条件能否叠加、效果采用快照还是实时读取，以及上限在何处生效。若百分比加成作用于已经包含其他百分比的结果，就会形成乘法增长；新增成长线时，应检查它与既有层级的组合，而不是只看单独数值。

成长维度只有在改变选择或行为时才具有独立意义。若等级、装备强化、突破和称号都只提供同一层的攻击百分比，它们虽然来自不同界面，实际仍是一条纵向成长线。

## 5. 战力评分的用途和限制

线性战力评分可表示为：

$$
CP=\sum_iw_iAttr_i
$$

其中权重 $w_i$ 依赖评价场景。控制、位移、无敌和团队协同不能通过脱离项目的固定数字换算。原教程给出的若干“技能等于多少战力”示例缺少战斗环境，不应作为通用参数。

战力评分可以承担三种不同工作：

1. 展示成长进度；
2. 粗略推荐内容难度；
3. 为匹配或自动配装提供输入。

三种用途不应默认共享一个公式。显示分强调稳定和可理解；内容推荐需要估计场景适配；竞技匹配还必须使用实际表现。若玩家能够堆高显示分却降低实战效率，评分会反过来误导决策。

## 6. 突破与转生

突破通常保留当前成长，只开放新的等级、属性或能力。转生则以重置部分进度换取永久收益。设计这类系统时，需要建立资产变化表：

| 资产 | 重置 | 保留 | 转换 | 说明 |
|---|---:|---:|---:|---|
| 等级 |  |  |  |  |
| 基础属性 |  |  |  |  |
| 装备 |  |  |  |  |
| 技能 |  |  |  |  |
| 货币与材料 |  |  |  |  |
| 内容解锁 |  |  |  |  |

转生后的回到原进度时间应短于首次成长，否则玩家只是在重复已经掌握的内容。永久收益也需要限制复利速度；若每次转生同时提高经验效率和战斗效率，循环周期可能迅速缩短并引起数量级膨胀。

突破若只提供全属性倍率，会扩大新老玩家的绝对差距。若它解锁新的能力选择，则要检查未突破玩家是否仍能参与主要内容，以及新能力是否造成不可逆的竞技优势。

## 7. 追赶与通胀

追赶机制的目标不是让新玩家立即等同于老玩家，而是降低旧阶段的时间成本，使玩家能够在可预期时间内进入当前主要内容。可以通过降低旧等级经验、提高旧材料产出、开放替代任务或减少过时门槛实现。

追赶效果应使用“到达当前内容门槛所需时间”衡量。仅提高经验倍率可能无法解决装备、技能和任务解锁造成的差距。

长期成长还需监控：

- 新版本的中位有效战力增长；
- 旧内容被跨越的比例；
- 旧资产被替代所需时间；
- 新玩家进入组队内容所需天数；
- 各成长线对总强度的边际贡献。

不存在适用于所有游戏的固定月通胀健康区间。合理增速取决于版本周期、内容寿命和是否存在赛季重置。

## 8. 验证步骤

1. 绘制每级经验、累计经验、预计升级时间和解锁内容。
2. 分别模拟高效率、普通、低活跃和回流玩家。
3. 检查阶段交界是否突然增加等待时间或资源种类。
4. 计算各成长线单独及组合后的强度贡献。
5. 测试转生或突破前后的回本时间和资产变化。
6. 记录新玩家到达当前内容门槛的完整路径。
7. 对曲线修改执行累计投入迁移和舍入对账。
