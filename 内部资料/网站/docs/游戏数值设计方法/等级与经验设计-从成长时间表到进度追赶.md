# 等级与经验设计：从成长时间表到进度追赶

等级经验表要回答的不是“曲线长什么样”，而是玩家按什么速度穿过游戏阶段。玩家实际感受到的是今天做哪些内容、多久升一级、何时开放新系统，以及落后后还要补多久才能回到当前主要内容。因此，等级经验设计应先建立成长时间表，再用真实经验来源反推每级需求，最后把结果放回关卡、系统开放和追赶模型中验证。

本文只处理角色等级和长期进度。装备、技能等独立养成线如何提供战斗能力，另见相关专题；玩家能力如何转成怪物和关卡强度，见《玩家成长与内容梯度设计》。本文的主要阅读任务是：完成一张可对账、可迁移、可追赶验证的等级经验模型。

## 1. 先把成长阶段排到同一张时间表

第一步不是选线性、指数或分段函数，而是写出玩家从创建角色到进入当前主要内容的阶段。阶段边界通常来自玩法变化：教学结束、系统开始展开、日常循环形成、版本内容开始承接长期参与。若为了公式整齐而均分等级，后续很难解释某一级为什么要慢下来或快起来。

| 阶段 | 目标累计时间 | 主要行为 | 新增内容 | 设计目的 |
|---|---:|---|---|---|
| 教学阶段 | 分钟级 | 主线、教学战斗 | 基础操作、首个技能 | 快速建立操作与目标 |
| 系统展开 | 小时级 | 主线、支线、首次副本 | 装备、养成、社交 | 逐步增加决策量 |
| 稳定成长 | 天级 | 日常、挂机、活动、副本 | Build 与长期目标 | 形成稳定玩法结构 |
| 当前版本 | 周或赛季级 | 高难、收集、竞争 | 版本内容 | 承接长期参与 |

时间表必须区分三个口径。自然时间表示从注册到达成目标经过多少天；有效游玩时间表示玩家实际投入多少小时；受限时间表示体力、每日次数和定时活动带来的等待。同样是三天升到目标等级，一名玩家可能实际玩十二小时，另一名玩家每天完成半小时日常即可到达。如果口径混在一起，后续无法判断问题来自经验总量、玩法效率还是时间门槛。

等级时间表还要和内容表使用同一条轴：

```text
累计自然时间
→ 玩家等级
→ 可参与玩法与每日经验来源
→ 主线或关卡位置
→ 系统开放与养成投放
→ 目标玩家能力
→ 内容难度
```

例如，提高某阶段经验副本的占比，会让参与玩家更早进入后续关卡；后续关卡若同时投放装备材料，玩家能力又会进一步提前。只改经验表而不检查关卡、系统开放和资源投放，常会把一个经验调整变成一串内容偏移。

## 2. 用经验来源反推单级需求

时间表给出“这一等级或阶段希望持续多久”。要把它写成配置，需要先估计目标玩家在该等级能获得多少经验。设等级 $L$ 的综合经验效率为 $R_L$，目标升级时间为 $T_L$，则该级经验需求初值为：

$$
EXP_L=R_L\times T_L
$$

这个公式用于把目标时间转换成经验需求。公式算完后，设计者要判断的是：如果 $R_L$ 来自目标玩家的真实行为，$EXP_L$ 是否能让该等级持续到计划的内容节点。$R_L$ 不能只取最高效率玩法，也不能只取怪物击杀经验；它应表示目标玩家在该阶段真实可获得的综合效率。

经验来自多个活动时，可写为：

$$
R_L=\sum_j F_{j,L}\times D_{j,L}\times E_{j,L}\times P_{j,L}
$$

其中 $F_{j,L}$ 是活动在统计周期内可参与的次数，$D_{j,L}$ 是单次参与时间，$E_{j,L}$ 是活动单位时间经验效率，$P_{j,L}$ 是目标玩家的参与或完成比例。如果项目使用“每日经验”而不是“单位时间经验”，可以直接计算各活动的单日贡献，再用目标升级天数反推需求。关键是所有变量采用同一统计周期。

经验需求和经验产出必须同时建模。只提高每级需求会延长升级时间，却不会说明玩家应通过哪些行为完成成长。挂机占比过高时，主动玩法对进度影响很弱；定时活动占比过高时，错过窗口会造成明显落后；单一副本效率过高时，它会成为事实上的必做内容；主线经验刚好填满升级需求时，玩家漏做内容就可能卡住；付费经验来源与基础产出相乘时，差距会随时间扩大。

每个阶段至少需要一张经验来源构成表：

| 来源 | 单次效率 | 次数或持续时间 | 单日总量 | 占比 | 是否可补领 | 是否受等级修正 |
|---|---:|---:|---:|---:|---|---|
| 主线 |  |  |  |  |  |  |
| 日常 |  |  |  |  |  |  |
| 副本 |  |  |  |  |  |  |
| 活动 |  |  |  |  |  |  |
| 挂机 |  |  |  |  |  |  |

标准值负责标定，玩家分层负责检查分布。设计者应分别计算高活跃、普通、低活跃和回流玩家，而不是只保留一个“标准日产出”。

## 3. 根据经验结构选择计算方式

不同项目的经验来源不同，不能共用一套简化公式。先确认经验结构，再决定用任务预算、刷怪效率还是每日资源反推。

任务驱动型成长先确定等级段内会完成多少任务，再把该段经验预算分配给任务。设等级 $L$ 的任务经验预算为 $B_L$，任务 $i$ 的权重为 $w_i$，则：

$$
Reward_i=B_L\times\frac{w_i}{\sum_j w_j}
$$

这个公式用于把同一等级段的经验预算分配给具体任务。公式后要检查的是权重是否反映耗时、难度、失败风险和剧情重要性。若同一级有一个短对话任务和一个精英战斗任务，平均分配经验会让轻量任务的单位时间收益过高。整数美化造成的总量差额需要回填到该等级预算，不能逐个四舍五入后不再对账。

任务型结构还要检查断点。若升级需求为 10,000，而主线任务累计只提供 9,600，玩家可能在剧情节点前被迫刷怪；若任务提供 12,000，玩家则可能提前升级并跳过为当前等级准备的内容。是否允许溢出由设计目标决定，但结果应当是规划，而不是配置误差。

刷怪或挂机驱动型成长先确定单位时间击杀数量和单怪经验：

$$
R_L=KillsPerHour_L\times ExpPerKill_L
$$

这个公式用于把战斗效率转成升级速度。算出 $R_L$ 后，再根据目标升级时间计算需求。任务和活动可以作为加速项加入，而不一定承担完整升级预算。此类模型必须计入停机、寻路、抢怪、死亡和背包整理；用训练场中的连续击杀效率代替真实效率，会系统性低估升级时间。

对刷怪游戏，还需要检查跨等级收益修正。若低级怪经验不衰减，高等级玩家可能长期留在高效率低风险区域；若衰减过强，组队和跨区探索会受限。修正函数应服务内容流动，而不是单纯阻止玩家找到高效率路线。

当经验主要来自体力、门票或每日次数时，升级速度由每日可用资源决定：

$$
DailyExp_L=EnergyPerDay\times ExpPerEnergy_L+FixedDailyExp_L
$$

这个公式用于估算自然日进度。公式后要分别检查免费恢复、储存上限、付费补充、活动赠送和溢出损失。若体力八小时回满，一天登录一次的玩家无法获得理论日产量。时间恢复型结构适合控制自然时间进度，却容易让有效游玩时间和成长速度脱钩。

## 4. 用曲线生成逐级表，但不要让曲线替代阶段设计

完成阶段时间和经验来源后，可以使用公式减少逐级配置量。常见形式有线性 $EXP_L=a+bL$、多项式 $EXP_L=aL^p+b$、指数 $EXP_L=ar^L$ 和分段函数。选择函数时，应比较实际输出，而不是根据名称判断“线性平缓、指数陡峭”。在有限等级区间内，多种函数可能产生近似结果。

真正需要检查的是：每级升级时间是否符合阶段目标；累计时间是否符合内容计划；阶段连接处是否出现突增或突降；调整参数后影响范围是否可控；数值取整后是否出现连续多级不变或异常跳点。长线项目通常更适合分段设计。教学阶段、系统展开阶段和长期阶段承担的任务不同，强行用一条公式贯穿全等级，会使局部调整牵动整条曲线。

项目表中可以为每个等级记录：

| 等级 | 单级时间 | 累计时间 | 单级经验 | 累计经验 | 主要经验来源 | 对应关卡 | 新开放系统 |
|---:|---:|---:|---:|---:|---|---|---|
|  |  |  |  |  |  |  |  |

等级很多时，不必手工配置每一行。可以用阶段参数生成逐级结果，但输出表必须显示每一级的实际时间和对应内容，便于检查。

## 5. 用累计投入处理版本迁移

版本修改经验曲线时，等级编号只表示玩家位于哪一段，累计经验才记录其在这条进度线上的投入。达到等级 $L$ 的累计经验为：

$$
C(L)=\sum_{n=1}^{L-1}EXP_n
$$

这个公式用于迁移和对账。设计者先用旧表计算玩家的累计投入，再在新表中寻找不超过该投入的最高等级，并把剩余经验放入新等级的当前进度。若直接把旧等级映射到同名新等级，可能导致投入增加或损失。

一种常见迁移流程是：计算玩家旧等级和当前级经验对应的累计投入；在新曲线中寻找不超过该投入的最高等级；将剩余经验放入新等级的当前进度；对整数舍入造成的差额进行对账；等级解锁、付费权益和任务状态另行映射。

经验只是玩家资产的一部分。若旧等级同时代表装备门槛、技能点和内容资格，迁移时需要逐项检查，不能用累计经验替代全部资产。

## 6. 追赶要按“到达当前内容的时间”验证

追赶的衡量单位应是新玩家或回流玩家到达当前主要内容需要多久，而不是单独看经验倍率。玩家可能等级已经追上，却仍缺少装备、技能、材料或前置任务。

常见手段包括降低旧阶段经验需求、提高旧阶段经验和材料产出、根据落后程度提供递减经验加成、合并过时任务和系统门槛、提供旧装备或关键能力的定向获取，以及允许错过的限时产出通过其他方式补回。

追赶不等于立即抹平所有差距。进入组队内容的基础能力可以快速追赶，收藏、外观和高阶构筑仍可保留历史积累。设计时要明确哪些差距缩短，哪些差距保留长期投入价值。

长期增长还要同时检查内容寿命。角色能力持续提高时，旧内容的相对难度会下降。成长速度是否健康，不能只看玩家战力增长率，还要看内容被跨越的速度。赛季制游戏可以周期性重置，长期养成游戏则需要控制复利和旧资产替代速度；判断标准应来自版本周期、内容供应能力和玩家回流路径。

建议持续记录新版本普通玩家到达主要内容的天数、各阶段单级时间和累计时间、经验来源实际占比、不同活跃层玩家等级分布、旧内容被跳过或碾压的比例、等级追上后装备和技能仍需补齐的时间，以及版本修改前后的累计投入差额。

## 7. 完整算例：从七日目标生成阶段经验表

下面使用一个虚构的长线 RPG 阶段说明计算过程。例子仅用于展示方法，不代表推荐时长。

**规则。** 设计目标是让普通玩家在第 4 天达到 30 级，在第 7 天达到 40 级。30—40 级期间，普通玩家每天预计获得：

| 来源 | 理论单日产出 | 参与率 | 有效单日产出 |
|---|---:|---:|---:|
| 主线与支线 | 18,000 | 90% | 16,200 |
| 日常任务 | 10,000 | 80% | 8,000 |
| 经验副本 | 12,000 | 70% | 8,400 |
| 挂机 | 7,000 | 100% | 7,000 |
| 定时活动 | 8,000 | 40% | 3,200 |
| **合计** | **55,000** | — | **42,800** |

普通玩家三天的有效经验预算约为：

$$
42,800\times3=128,400
$$

**玩家状态。** 普通玩家按表中参与率完成内容；高活跃玩家每天获得 55,000；低活跃玩家每天只有 25,000。阶段内计划 34 级开放新养成，39—40 级承担阶段收束。

**结果。** 128,400 是 30—40 级累计需求初值，可分配为：

| 等级 | 目标时间/天 | 需求经验 | 主要节点 |
|---:|---:|---:|---|
| 30→31 | 0.20 | 8,560 | 阶段入口 |
| 31→32 | 0.22 | 9,416 |  |
| 32→33 | 0.24 | 10,272 |  |
| 33→34 | 0.26 | 11,128 | 新副本预告 |
| 34→35 | 0.34 | 14,552 | 新养成开放 |
| 35→36 | 0.30 | 12,840 |  |
| 36→37 | 0.31 | 13,268 |  |
| 37→38 | 0.33 | 14,124 |  |
| 38→39 | 0.38 | 16,264 | 阶段检查 |
| 39→40 | 0.42 | 17,976 | 阶段目标 |
| **合计** | **3.00** | **128,400** |  |

高活跃玩家约 2.33 天完成，低活跃玩家约 5.14 天完成。若 30—40 级主线计划提供 48,600 经验，日常三天提供 30,000，副本及其他来源提供 49,800，合计正好为 128,400；若某次任务删减使主线少发 6,000，就必须决定由其他来源补齐、缩短阶段需求，还是有意延长进度。

**判断。** 这张表当前能解释普通玩家三天穿过 30—40 级，也暴露出高低活跃差距。差距是否可接受，需要结合玩法开放和社交门槛判断。普通玩家预计第 5 天开放某副本，则怪物和奖励应使用第 5 天的玩家能力基准，而不是简单使用 35 级裸装属性。这样经验进度才真正连接到内容数值。

## 8. 成长复盘与异常诊断

配置完成后，需要按天或按有效游玩小时模拟玩家成长。每个模拟角色至少记录：

```text
当前自然日
当前有效游玩时间
等级与当前经验
当天参与的经验来源
体力和次数的未使用量
已开放系统
关键装备与技能进度
主线或关卡位置
```

模拟不应默认玩家每天完成所有内容。至少建立高活跃、普通、低活跃和回流四条路径：高活跃充分利用自然恢复；普通完成主要日常，偶尔错过限时活动；低活跃只完成核心内容，存在体力溢出；回流初始落后，获得追赶加成和旧内容压缩。

出现偏差时，先根据现象定位变量：

| 现象 | 优先检查 |
|---|---|
| 全体玩家都晚于目标升级 | 总需求、基础日产出、完成率假设 |
| 只有低活跃玩家严重落后 | 定时活动占比、体力溢出、补领规则 |
| 玩家集中刷单一内容 | 单位时间效率、次数限制、其他玩法的机会成本 |
| 主线频繁被等级卡住 | 任务预算、失败率、经验溢出和阶段连接 |
| 等级追上但无法参加当前内容 | 装备、技能、材料和前置任务的追赶缺口 |
| 新系统开放后进度突然加速 | 新玩法产出是否重复计入，效率是否与旧来源叠加 |
| 改版后老玩家出现经验损失 | 累计投入映射和取整对账 |

上线后，理论完成率应替换为真实数据。建议按等级和玩家分层观察经验来源占比、单日经验分布、升级时长中位数与分位数、体力溢出率、主线卡点和追赶完成时间。平均升级时间会掩盖双峰分布，至少同时查看 P25、P50、P75 和 P90。

## 9. 工作表结构

一个可维护的等级经验工作簿可以分成五层：

1. **阶段输入**：等级段、目标时间、活跃假设和解锁节点；
2. **产出输入**：活动次数、时长、效率、参与率和补领规则；
3. **逐级计算**：单级经验、累计经验、单级时间和累计时间；
4. **内容映射**：关卡、玩法开放、资源投放和能力阶段；
5. **检查输出**：阶段跳点、来源占比、玩家分层和迁移差额。

不要把阶段参数、逐级结果和人工修正混在一张表里。输入与输出分开后，才能知道某个异常来自目标修改、公式错误还是手工覆盖。

## 10. 发布前检查

- [ ] 每个成长阶段是否有明确的目标自然时间和有效游玩时间？
- [ ] 每级需求是否由目标时间和真实经验来源反推？
- [ ] 是否分别计算高活跃、普通、低活跃和回流玩家？
- [ ] 是否检查某项活动被经验效率推成事实上的必做内容？
- [ ] 阶段连接处是否存在升级时间突变？
- [ ] 等级、关卡、系统开放和玩家能力是否位于同一时间轴？
- [ ] 版本迁移是否按累计投入对账？
- [ ] 追赶是否同时覆盖经验、装备、技能和任务门槛？
- [ ] 是否能从配置表追溯每个等级的参数来源？

## 来源与核验说明

本文实际使用并重新组织了以下资料中的方法：

- 《游戏数值策划完全教程》第 2 章：经验曲线、累计经验、追赶和长期增长主题；
- 青云诀项目资料《升级经验.xlsx》：阶段升级时间、经验来源占比、逐级经验、关卡进度和累计时间之间的工作表连接；
- 青云诀项目资料《角色属性.xlsx》《怪物属性.xlsx》：等级进度与玩家能力、内容属性的连接方式，仅用于分析表结构，不采用项目具体参数作为通用结论；
- 明澈流风《游戏数值建模 V1.0》：分段经验曲线、刷怪经验反推和任务经验权重分配；
- 《游戏数值设定》：每日经验基数、系统产出份额和升级意义等问题清单；
- 本库《数值建模：从体验目标到标准模型》：目标时间、标准玩家和模型依赖方法。

原资料中的具体升级时长、活动占比、付费效率和项目参数均未作为行业通用值收录。
