# 匹配与排位：MMR、段位、组队与等待时间

匹配系统同时优化实力接近、等待时间、网络质量、位置需求和队伍结构。不存在只靠一个分数就能满足全部目标的算法。隐藏能力分负责估计，显示段位负责反馈，两者应分开设计。

这篇文章的主要任务，是把一次匹配与排位设计拆成可验证流程：先估计能力，再定义候选对局质量，随后处理组队、段位、新手和回流，最后用等待尾部与预测校准诊断问题。

## 1. 能力估计与候选筛选

### 1.1 先定义能力估计要表达什么

能力分至少记录估计值和不确定性。新玩家样本少，应允许分数快速变化；稳定玩家的变化应较慢。组队、位置变化、赛季重置和长期未活跃都会改变不确定性，因此它们不能只作为展示层事件处理。

更新不能只看胜负。若使用局内表现，需要防止玩家为了评分优化数据而牺牲团队目标；表现指标也可能对不同角色和职责不公平。能力模型的目标是预测对局结果，而不是奖励所有看起来漂亮的个人数据。

### 1.2 用质量函数选择候选对局

一场候选对局可以综合评价：

$$Q=w_sQ_{skill}+w_nQ_{network}+w_rQ_{role}+w_pQ_{party}$$

各项权重取决于模式。系统还需设置不可突破的护栏，例如最大延迟、队伍人数差和允许的实力差。质量函数负责比较候选项，护栏负责阻止明显不可接受的对局；两者不要混成一个模糊分数。

等待时间增长时可以逐步扩大搜索范围，但要记录每一步牺牲了什么。例如匹配开始时限制预测胜率 45%—55%、延迟低于 60ms、队伍规模相同；等待 30 秒后放宽到 42%—58%，60 秒后允许相邻地区，但延迟仍不能超过 100ms。每次扩张都要记录命中的规则。

平均等待时间正常，不代表尾部玩家体验正常。若 P50 等待 20 秒、P95 达到 180 秒，平均值无法代表尾部。应按地区、分段、位置和组队规模寻找池容量问题，而不是全局放宽实力差。

### 1.3 单独估计预组队优势

预组队可能拥有沟通、阵容和稳定协作优势。修正应基于真实结果按队伍规模、分段和模式估计，不能给所有组队套同一固定加分。五人队对五人队、五人队对散人和双排混入团队战应分别观察。

组队修正的决策要看目标场景。如果五人队互打时预测准确，但五人队对散人时预测偏高，问题在队伍结构而不一定在个人 MMR。若双排只在某些位置组合中异常，修正应落到位置和阵容协同，而不是统一惩罚所有双排。

## 2. 段位反馈与特殊人群

### 2.1 把显示段位当作反馈系统设计

显示段位承担目标感、保护和赛季节奏，不必与 MMR 一一对应。需要明确晋级、降级、保护分、赛季软重置和长期未活跃规则。

若段位长期高于真实匹配能力，玩家会觉得同段位对手差异巨大；若段位变化完全跟随隐藏分，反馈又可能过于剧烈。两者的差值和收敛速度需要监控。设计决策应说明哪一部分是能力估计，哪一部分是体验保护，避免用段位规则掩盖匹配质量问题。

### 2.2 处理新手、回流与小号

新手定位需要较高不确定性、保护性对局和快速收敛。回流玩家应根据停留时间和版本变化提高不确定性，而不是直接清空历史。小号检测只能作为辅助证据，不能因为少数高表现对局就永久判定。

这类玩家的边界在于误伤成本。过慢收敛会让强小号破坏新手局，过快惩罚又会把少数状态好的新玩家推入不适合的环境。诊断时要同时看预测胜率、对局体验和后续留存，不能只看定位速度。

## 3. 线上诊断与发布校验

### 3.1 用监控指标诊断匹配问题

至少监控等待时间分位数、双方能力差、预测胜率分布、预组队差异、网络质量、位置补位率、重赛率、退出率和连续极端对局。匹配公平应看每场预测质量及尾部，不能只看全服平均胜率接近 50%。

评分校准要把模型预测胜率分桶，再与真实胜率比较。预测 60% 的对局长期只赢 52%，说明评分或队伍修正未校准。赛季更新后也要重新检查，因为地图和角色变化会改变能力表现。

配置与监控需要保留搜索阶段、允许分差、网络阈值、位置规则、组队修正、段位映射和重置参数；同时监控每个阶段的成局率、取消率、质量和后续留存。这样才能知道问题来自池容量、质量函数、扩张规则、队伍修正，还是显示段位反馈。

### 3.2 发布前检查

- [ ] 能力估计是否包含不确定性？
- [ ] 搜索扩张是否有质量护栏？
- [ ] 预组队修正是否按真实场景估计？
- [ ] MMR 与显示段位职责是否分开？
- [ ] 是否监控等待与实力差的尾部？
