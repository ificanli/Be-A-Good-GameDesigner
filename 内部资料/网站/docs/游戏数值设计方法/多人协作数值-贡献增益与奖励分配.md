# 多人协作数值：贡献、增益与奖励分配

多人奖励应鼓励真实合作，而不是让组队成为强制税或多开工具。设计时要区分个人投入、团队结果和关系维护，避免只用伤害量评价所有职责。

## 1. 组队收益

组队加成需要覆盖沟通成本、组队等待和失败风险，但不应让单人路径失去基本完整性。加成可以随人数边际递减：

$$Bonus(n)=B_{max}(1-e^{-k(n-1)})$$

公式只是生成初值。实际还要检查预组队、多开、带小号和高低等级混队。

## 2. 贡献模型

贡献应围绕玩法目标定义，可包含伤害、承伤、治疗、控制、机制执行、资源运输和团队增益。各指标需要上限和场景权重，防止刷无效伤害或故意承伤。

贡献分适合分配部分奖励和识别异常，不应决定全部收益。辅助行为难以完整量化，纯排名分配会让玩家互相竞争而不是合作。

## 3. 奖励分层

多人奖励可拆为：

- 参与奖励：满足基础行为即可获得；
- 成功奖励：团队完成目标后共同获得；
- 贡献奖励：奖励额外有效投入；
- 稀有奖励：通过个人掉落、轮转或团队分配产生；
- 长期奖励：公会、师徒和关系成长。

参与奖励防止辅助角色吃亏，贡献奖励限制挂机。稀有物分配应提前说明个人归属、需求投掷、竞拍或轮转规则。

## 4. 公会与公共资源

公会资源需要记录个人来源、公共库存、使用权限和退出规则。少数管理者能永久控制公共资产时，容易形成垄断和纠纷。重大消耗可使用日志、权限分层、冷却和集体确认。

公会成长不应只按在线时长累计。应奖励有效目标，同时避免大公会凭人数线性碾压。可使用成员有效贡献上限、边际递减或规模分组。

## 5. 师徒和追赶

师徒双方都应获得与目标一致的价值。若奖励只取决于重复带低级副本，会诱发流水线收徒。更合适的指标包括新玩家完成关键学习、独立通关和关系持续时间。

追赶加成应帮助新玩家进入共同内容，但不能让老玩家通过多开小号无限复制收益。

## 6. 诊断

观察组队率、等待时间、队伍成功率、角色职责分布、贡献分布、踢人率、奖励集中度、公会规模优势和可疑关联账号。高组队率不一定代表社交健康，也可能是奖励迫使玩家组队。

## 7. 奖励分配示例

一次四人副本奖励拆为：所有完成者获得 70% 基础奖励；满足最低有效行为获得 20%；剩余 10% 用于机制执行和额外贡献。治疗和控制使用独立指标，不与伤害统一排名。

若某玩家伤害低但承担关键打断，仍应通过成功和机制层获得完整主要奖励。挂机玩家只拿进入奖励或无奖励，具体阈值需防止误伤新手。

## 8. 反利用检查

测试多开账号互刷、重复带小号、故意延长战斗刷治疗、制造无效伤害、公会成员轮流输送资源和队长踢人独占奖励。限制应作用于可利用路径，不要让正常合作承担过高验证成本。

## 9. 工作表

记录行为事件、有效条件、贡献上限、团队奖励、个人奖励、公共库存、权限和异常规则，并按职责提供黄金样例。

## 发布前检查

- [ ] 组队加成是否覆盖成本但不排除单人？
- [ ] 贡献是否覆盖不同职责并防止刷分？
- [ ] 团队成功和个人贡献奖励是否分层？
- [ ] 公共资产是否有日志和权限规则？
- [ ] 是否测试多开、带小号和大公会垄断？
