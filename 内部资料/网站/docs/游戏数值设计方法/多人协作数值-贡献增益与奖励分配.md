# 多人协作数值：贡献、增益与奖励分配

多人奖励应鼓励真实合作，而不是让组队成为强制税或多开工具。设计时要区分个人投入、团队结果和关系维护，避免只用伤害量评价所有职责。

这篇文章只处理一个设计任务：怎样从合作目标出发，确定组队收益、贡献评价、奖励分层和反利用规则，并用诊断数据判断奖励是否真的支持合作。

## 1. 合作目标与贡献口径

### 1.1 先说明组队为什么值得奖励

组队加成需要覆盖沟通成本、组队等待和失败风险，但不应让单人路径失去基本完整性。加成可以随人数边际递减：

$$Bonus(n)=B_{max}(1-e^{-k(n-1)})$$

公式只是生成初值。真正的决策要看它在预组队、多开、带小号和高低等级混队中怎样被使用。若加成过低，玩家会把组队视为负担；若加成过高，单人路径会被排除，组队也可能变成多开或流水线带号。

### 1.2 按玩法目标定义贡献

贡献应围绕玩法目标定义，可包含伤害、承伤、治疗、控制、机制执行、资源运输和团队增益。各指标需要上限和场景权重，防止刷无效伤害或故意承伤。

贡献分适合分配部分奖励和识别异常，不应决定全部收益。辅助行为难以完整量化，纯排名分配会让玩家互相竞争而不是合作。因此，贡献模型先回答“哪些行为对目标有效”，再决定它影响哪一层奖励。

### 1.3 把团队结果和个人贡献分层

多人奖励可拆为参与奖励、成功奖励、贡献奖励、稀有奖励和长期奖励。参与奖励用于保障满足基础行为的玩家；成功奖励在团队完成目标后共同发放；贡献奖励给额外有效投入；稀有奖励通过个人掉落、轮转或团队分配产生；长期奖励服务公会、师徒和关系成长。

这种分层可以同时处理公平和合作。参与奖励防止辅助角色吃亏，贡献奖励限制挂机，成功奖励让玩家关心团队目标。稀有物分配应提前说明个人归属、需求投掷、竞拍或轮转规则，否则奖励本身会制造纠纷。

一次四人副本可以这样拆奖励：所有完成者获得 70% 基础奖励；满足最低有效行为获得 20%；剩余 10% 用于机制执行和额外贡献。治疗和控制使用独立指标，不与伤害统一排名。若某玩家伤害低但承担关键打断，仍应通过成功和机制层获得完整主要奖励。挂机玩家只拿进入奖励或无奖励，具体阈值需防止误伤新手。

## 2. 长期协作与公共资源

### 2.1 公会和公共资源要防垄断

公会资源需要记录个人来源、公共库存、使用权限和退出规则。少数管理者能永久控制公共资产时，容易形成垄断和纠纷。重大消耗可使用日志、权限分层、冷却和集体确认。

公会成长不应只按在线时长累计。应奖励有效目标，同时避免大公会凭人数线性碾压。可使用成员有效贡献上限、边际递减或规模分组。这里的目标不是惩罚大公会，而是防止规模本身压过组织质量和个人有效投入。

### 2.2 师徒和追赶要服务共同内容

师徒双方都应获得与目标一致的价值。若奖励只取决于重复带低级副本，会诱发流水线收徒。更合适的指标包括新玩家完成关键学习、独立通关和关系持续时间。

追赶加成应帮助新玩家进入共同内容，但不能让老玩家通过多开小号无限复制收益。判断边界时，要同时看新玩家是否更快进入团队玩法，以及可疑关联账号是否通过重复带号获得异常收益。

## 3. 线上诊断与发布校验

### 3.1 用诊断数据判断奖励是否支持合作

诊断至少观察组队率、等待时间、队伍成功率、角色职责分布、贡献分布、踢人率、奖励集中度、公会规模优势和可疑关联账号。高组队率不一定代表社交健康，也可能是奖励迫使玩家组队。

反利用测试要覆盖多开账号互刷、重复带小号、故意延长战斗刷治疗、制造无效伤害、公会成员轮流输送资源和队长踢人独占奖励。限制应作用于可利用路径，不要让正常合作承担过高验证成本。

工作表应记录行为事件、有效条件、贡献上限、团队奖励、个人奖励、公共库存、权限和异常规则，并按职责提供黄金样例。这样复盘时才能判断问题来自目标定义、贡献口径、奖励分层，还是反利用规则过松或过严。

### 3.2 发布前检查

- [ ] 组队加成是否覆盖成本但不排除单人？
- [ ] 贡献是否覆盖不同职责并防止刷分？
- [ ] 团队成功和个人贡献奖励是否分层？
- [ ] 公共资产是否有日志和权限规则？
- [ ] 是否测试多开、带小号和大公会垄断？
