# 11 · 迭代与止损

本篇只完成一个阅读任务：根据试玩证据决定下一轮是局部修复、结构返工、范围降级，还是停止。

原型出现问题后，团队最容易沿着已有实现继续加功能。有效迭代不是“再做一版看看”，而是先判断当前证据支持哪一种处理层级。止损也不是否认已投入的工作，它阻止缺少核心证据的方案继续扩大成本。

《五球满贯》的迭代要围绕已被有限证据支持的资产展开：多球碰撞和一杆多撞在作者试玩中比其他候选有更明确的即时正反馈。但这只说明它值得继续验证，不说明外部玩家已经认可，也不说明两小时长局和徽章流派已经成立。

## 1. 保护已验证资产

### 1.1 先保护得到支持的体验资产

修改前先写出“什么不能被无意破坏”。《五球满贯》的资产不是第一版数值，也不是某个具体 UI，而是玩家通过发射准备、真实碰撞和墙加工得到一杆多撞的期待与释放。后续构筑、提示、桌面目标和结算表现，都不应压住发射节奏或让得分变成自动播放。

保护资产不等于冻结所有规则。若辅助线不准，就修实现；若结算看不清，就改表现；若功能墙太晚出现，就调节桌面。冻结的是玩家为何喜欢，而不是导致该体验的第一版实现细节。

《叠层矿场》提供了反面提醒。旧原型实现过三合生成材料、取牌推进工作和工具反改牌堆；后续试玩又表明，这些可见因果并未自动形成足够爽感。重做时可以保留“取牌改变生产”的关系，但必须重新验证释放感，不能把旧实现当作已证资产。

## 2. 选择迭代层级和改动粒度

### 2.1 按证据选择处理层级

局部修复适用于核心行为已经出现，且问题集中在数值、提示、反馈或节奏。《五球满贯》若玩家愿意规划功能墙，但经常因为预测误差失败，就应先迭代碰撞一致性、力度曲线、停止节奏和结算表现。规则—行为—观察—结论链是：规则仍产生规划行为，观察到的失败来自实现或表达，结论是修复后复测。

结构返工适用于概念仍有价值，但当前循环没有兑现。《扫雷占城》曾被反馈更像“狱国争霸加扫雷”，与预期的轻量领土吞并存在偏差。应重新确认安全格怎样直接形成领土、0 连锁如何制造扩张高潮，而不是先添加兵种和成长。

范围降级适用于核心风险仍可验证，但完整方案超出周期。《坠楼消除》从三关和 Boss 降为单关，仍保留消除支撑、坠落清场与棋盘缩短，因此降级后仍能回答核心问题。降级若删掉关键后果，就不再是节省范围，而是换了测试问题。

淘汰适用于玩家理解且实现稳定，主循环仍没有选择、技巧或期待；或者核心效果无法在预算内达到可用质量。此时继续加内容只会增加退出成本。淘汰记录应说明证据和可回收机制。

### 2.2 每轮迭代只提出一个可复测改变

迭代记录要把修改连接到玩家行为，而不是只写功能名。

```text
观察到的问题：
根因假设：
准备修改的规则：
预期改变的玩家行为：
可能损失的已有乐趣：
复测局面和指标：
未达到时的下一步：
```

“增加更明显的墙球连线”不是最终目标；预期行为应写成“首玩者能指出哪颗球被染色，并在下一杆主动规划一次特殊墙”。若复测后玩家看懂了染色但仍不规划，结论应转向激励和压力，而不是继续加提示。

一次迭代尽量只改变一个关键关系。若同时重做输入、数值、教学和美术，反馈改善也无法归因。团队会得到一个更顺眼的版本，却不知道哪条证据变强。

### 2.3 结构返工也要缩小到切片

返工不等于整项目推倒重写。先选择一个决定性关系，做对照版本。《扫雷占城》若问题是翻格没有直接产生领土扩张，可以用相同地图制作两个规则切片：安全格立即染色并扩边；安全格只作为道路，军队经过后再占领。让玩家在短局中比较扩张反馈和路线判断，再决定主结构。

《叠层矿场》从七格三合转向完整经营后，也不应一次性加入所有《堆叠大陆》系统。先验证营地的即时需求是否会改变下一张矿牌选择；若没有，双区域仍然割裂。结构测试要比完整重制更小，否则又会被内容和表现污染。

## 3. 设置止损和知识回收

### 3.1 在修改前设置停止条件

停止条件要先写，避免结果不佳时不断降低标准。可以使用这些门槛：多数首玩者在解释后仍不使用核心机制；修复实现后，精彩操作与普通操作仍无显著差异；为让核心可读，需要超过项目可承受的信息或内容成本；连续两轮结构修改没有改善同一关键行为；原型最有趣的部分与立项承诺已经变成不同玩法。

停止可以是暂停、回到候选池或彻底淘汰，不必只有一种处理。《五球满贯》若最终证明玩家喜欢纯台球碰撞，却不愿意围绕数字组合和功能墙规划，团队要么重写体验承诺，要么停止当前候选，而不是把组合系统藏到后台。

### 3.2 回收失败中的知识

失败方案应拆成三部分保存：已证伪的完整方案与原因；尚未证伪、可以迁移的抽象关系；实现中可复用的工具、交互或测试方法。

《怪物拍卖行》的完整表达因高度相似产品而淘汰，但“购买改变后续价格、竞争者欲望和系统供给”仍是可迁移关系。回收抽象机制时必须换状态载体后重新查重与验证，不能只换题材返场。

每轮迭代结束保存版本、假设、修改、结果和结论。被否定的方向不得只从文档删除，否则团队会在数月后重复讨论。日志还应记录“为什么当时合理”，避免用后见之明把所有失败描述成明显错误。

## 4. 排除假迭代

### 4.1 避免假迭代

三类修改最容易冒充进展：用 Roguelike 奖励掩盖即时玩法无聊；用更多教程解释本身缺少因果的规则；用特效放大没有状态意义的结果。它们可能提高短期满意度，却不增强核心证据。迭代记录应始终回到玩家动作和局面变化。

### 4.2 来源说明

本文依据项目路线图、原型验收、淘汰记录与核心乐趣诊断方法整理。案例中的保留、返工和淘汰结论都是对应版本下的阶段决策，不是对玩法普遍价值的最终判断。
