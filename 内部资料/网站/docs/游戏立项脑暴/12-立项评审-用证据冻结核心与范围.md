# 12 · 立项评审：用证据冻结核心与范围

本篇只完成一个阅读任务：用已有证据决定项目是否进入更昂贵的下一阶段，并写清冻结什么、继续验证什么、何时停止。

立项评审不是选分数最高的创意，也不是确认策划案已经足够完整。它发生在风险排序、最小原型、完整局、试玩观察和迭代记录之后。若前面没有证据，评审会只能比较愿景、包装和表达能力。

《五球满贯》的评审重点不是“它已经有多少桌和徽章”，而是弹射、真实碰撞、功能墙加工和组合得分是否形成了可复现的玩家行为；长局目标、外部玩家规划率、爆仓率和目标设备性能还有哪些未知。

## 1. 准备证据化立项包

### 1.1 立项包按证据依赖组织

第一部分是一页产品定义。写明目标用户、平台、单局时长、体验承诺、主要输入、胜负条件和产品目的。评审者应能从这一页知道项目准备提供什么体验。对《五球满贯》来说，体验承诺应落在“通过真实弹射和一杆多撞准备组合得分”，而不是泛泛写“休闲策略碰撞”。

第二部分是玩家动词与核心因果：

```text
玩家反复做什么
→ 对象发生什么变化
→ 留下什么局面
→ 为什么下一次选择不同
```

《五球满贯》应写成：玩家拖拽发射数字球，球经过真实碰撞和特殊墙加工，进入组合槽并触发得分或徽章，结算结果改变下一杆目标。若动词链主要是点击领取、等待与整理，需要解释乐趣从何产生。

第三部分是假设与证据表。不同成熟度必须分开写，不能都叫“核心通过”。

| 假设 | 当前证据 | 证据等级 | 未知项 | 下一步 |
|---|---|---|---|---|
|  |  | 主张/实现/观察/复现 |  |  |

《五球满贯》可以把“作者试玩中弹射手感优于其他候选”列为有限观察支持，把外部玩家是否主动规划功能墙、两小时目标曲线是否成立、移动端连续重开是否稳定列为尚未验证。自动测试能证明规则可运行，不能单独证明体验好玩。

第四部分是风险与生产范围。列出体验、技术、内容和商业风险，附最低验证方法。范围分为下一阶段必须完成、核心通过后再做和明确不做。还要估算内容生产模式：主要依赖规则组合、程序生成还是手工关卡。

第五部分是查重与市场位置。记录最相近产品、相同高频操作和本方案新增判断。市场数据可以说明用户与竞争环境，不能替代核心玩法证据。《怪物拍卖行》因高度相似产品而淘汰，说明查重结论可以直接改变候选命运；但“购买改变后续价格、竞争者欲望和系统供给”这类抽象关系仍可回收后重新验证。

## 2. 用硬门形成评审结论

### 2.1 用硬门评审，不让平均分掩盖短板

加权评分可以帮助排序，却不应让美术表现、商业空间或个人偏好抵消核心证据不足。硬门应逐项回答：玩家能否理解主要输入和目标；核心动作是否有即时反馈；是否至少存在两个理由不同的选择；当前选择是否改变未来局面；失败是否可以归因；核心能否在预算内实现；未知风险是否有明确验证计划。

任一核心门未过，结论应是继续验证或返工，而不是用总分批准立项。《五球满贯》如果弹射反馈强，但外部玩家始终不使用功能墙规划，不能因为“手感好”和“商业空间大”直接进入完整生产。合适结论应指向下一轮验证：改墙加工表达、增加规划压力，或缩小到纯碰撞体验后重新评审。

### 2.2 评审结论必须能执行

评审结论只有四类。进入下一阶段，表示核心证据达到当前门槛，范围与风险可控；批准的是下一阶段预算，不是保证最终成功。附条件通过，表示部分证据成立，但必须先完成指定验证。返回原型，表示主要未知项仍能低成本验证，或测试被实现问题污染。停止，表示核心假设被否定、成本不可接受或差异不足。

例如，若《五球满贯》的核心输入已经稳定，三名首玩者能在一分钟内完成闭环，其中两人主动使用功能墙，但长线徽章关系和目标设备性能尚未验证，结论可以写成“附条件进入四周预制作”：第一周验证十个徽章或功能墙关系与移动端性能，未达到门槛则返回原型。不能写成笼统的“创意好，建议立项”。

结论还应指定负责人、版本与复审日期。没有时间点的附条件通过，往往会在开发中自动变成正式通过。

## 3. 冻结核心与下一阶段证据

### 3.1 冻结核心不变量，而不是冻结全部细节

立项后应冻结三至五条核心不变量。它们是后续开发不能静默改变的承诺。

```text
数字球必须通过真实碰撞进入组合；
特殊墙只加工实际撞墙的激活球；
组合得分必须能追溯到玩家这一杆准备；
辅助线、碰撞和结算必须使用一致规则；
胜负与重开必须让玩家知道下一局可改变什么。
```

数值、内容数量、界面布局和具体表现可以继续迭代。其他项目也有自己的不变量：矿洞取牌必须受遮挡关系约束；武器必须可见地沿蛇身加工并从尾部释放。若开发发现核心不变量无法成立，应触发重新评审，而不是静默改变产品。

### 3.2 下一阶段目标仍然写成证据

立项后也不能立刻把计划改成功能清单。阶段目标应写成可观察结果：

```text
让首玩者在一分钟内独立完成核心闭环；
让三种玩家策略都能完成一局并产生不同代价；
验证十个组件能否形成至少三条规则不同的构筑；
验证目标设备上连续十次重开无阻断问题。
```

功能只是取得这些证据的手段。阶段结束时，根据证据再次决定扩大、修正或停止。

## 4. 组织会议并沉淀模板

### 4.1 按会议顺序保护证据

评审会议应先演示未剪辑的真实玩法，不先讲愿景；由测试负责人陈述观察与反证；设计者解释核心因果和修改历史；制作岗位评估技术与内容风险；对照硬门逐项作结论；最后才讨论市场、商业和扩展机会；同时记录不同意见与需要补证的项目。

这个顺序可以减少完整提案和演示包装对核心证据的遮蔽。市场和商业不是不重要，而是不能先替核心玩法投票。


### 4.3 来源说明
