# 04 · 玩法融合：如何判断两个玩法是否真正融合

两个成熟玩法放进同一产品，不会自动融合。玩家先在系统 A 获得资源，再到系统 B 消耗资源，只说明两个循环交换了东西。要判断它们是否真正融合，你要看同一次高频决策是否同时影响两边，以及一边的结果是否改变下一次在另一边的选择。

下文用《叠层矿场》贯穿整个判断。这个原型曾尝试让“取出未遮挡矿牌”同时改变矿牌叠层和营地经营：玩家拿牌后改变叠层结构，矿工完成作业后再移除岩石、暴露新牌。规则图上存在双向箭头，但后续试玩仍觉得两个区域轮流工作。这个案例适合说明一个关键事实：逻辑上有联系，不等于体验上已经融合。

## 1. 定位融合对象

### 1.1 先找到唯一主动作

先写下玩家最常做、最能体现技巧的动作。找不到这个动作，就无法判断融合，因为你不知道两个系统是否服务同一次决策。

在《叠层矿场》中，候选主动作是“取出一张未遮挡矿牌”。这个动作至少要同时回答两类问题。它怎样改变矿层的遮挡、暴露和可达性？它又怎样满足营地当下的配方、食物、金币或工具需求？若玩家只是在矿洞里把可见牌拿完，再回营地集中经营，主动作就被拆成了两段。矿洞负责供给，营地负责消耗，两者只是串联。

判断主动作时，还要看构筑或经营是否把玩家带离核心场景。如果营地只在回合外提供永久加成，而下一次取牌仍只看矿层局面，营地不是融合的一半。它只是成长层。要让营地进入主动作，营地状态必须改变“现在拿哪张牌更好”的判断。

《五球满贯》反驳了一个常见误判：有构筑不一定割裂。它的主动作是瞄准并发射。一次击球既决定物理碰撞，也决定收入哪些数字球、哪颗球触发特殊墙，以及组合是否接近爆仓。构筑没有把玩家带离球桌，所以它没有把主动作拆开。

## 2. 验证结构不可拆分

### 2.1 用三项测试检查结构

找到主动作后，不要立刻给等级。先做三项测试。三项测试的目标不是证明方案好玩，而是判断两个系统有多难拆开。

#### 删除测试

删除其中一个系统，看另一边是否仍有完整目标、压力和胜负。

如果删掉营地，《叠层矿场》还可能保留一个拿矿牌、翻开遮挡、追求更高收益的叠层小游戏。如果删掉矿层，营地也可能变成一个等待资源、完成配方、升级设施的经营小游戏。两边都能独立运行时，融合度不会高。只有删除一边会让主循环失去关键判断，关系才变深。

删除测试也能暴露伪共享。画面同屏、题材相同、资源名字相同，都不能代替结构依赖。玩家必须因为一边的存在而改变另一边的核心选择。

#### 替换按钮测试

把系统 A 替换成“点击按钮，直接获得同等资源”，再看系统 B 是否基本不变。

如果《叠层矿场》的叠层区可以替换为“领取三份随机资源”，而营地经营几乎不变，产品核心就更接近《堆叠大陆》的资源入口变体。此时矿层只是在包装资源产出，通常停留在 1 级。要提高融合，深层可见信息、遮挡顺序和营地即时需求必须共同决定取牌。营地的工具和设施也要反过来改变矿层的遮挡、可达性或风险。

这个测试不要求资源系统消失。资源可以存在，但资源不能是唯一关系。若玩家只需要问“这张牌给多少木头、石头或金币”，而不需要问“这张牌会打开什么空间、堵住什么机会、改变下一轮什么风险”，叠层没有真正进入经营判断。

资源交换不够，通常还需要一个可见承载物。其他案例只在这里作为反例，用来反驳“数值换算就是融合”的误判。《五球满贯》的数字球同时是物理实体和组合素材。《坠楼消除》的建筑高度同时是棋盘、武器和防线。《扫雷占城》的公开道路同时帮助双方行军。这些关系不证明产品已经好玩，只说明共享对象、共享状态或共享后果比抽象资源交换更容易形成融合。

#### 双向反馈测试

最后只写一次双向反馈，避免把同一件事说成两张图。用下面两句话检查：

```text
系统 A 的哪个状态，改变系统 B 中哪些选项的价值？
系统 B 的哪个结果，改变系统 A 下一次怎样操作？
```

在《叠层矿场》中，第一句话可以是：矿层的遮挡、深层可见信息和可取牌，改变营地配方、食物、金币和工具路线的价值。第二句话必须反过来成立：营地缺食物、缺金币或等待某个配方时，会改变矿洞中不同可取牌的优先级。工具和设施会改变下一轮矿层的遮挡、可达性或风险。

只有第一句话成立，通常仍是单向供给。两句话都成立，才可能达到 2 级。如果同一次取牌就是两条反馈的交汇点，它才接近 3 级。

### 2.2 按不可拆分程度给等级

融合度衡量两套系统的不可拆分程度。它不衡量题材统一程度，也不直接衡量好玩程度。

| 等级 | 关系 | 在《叠层矿场》中怎样判断 |
|---:|---|---|
| 0 · 主题同居 | 只共享题材、包装或画面 | 删除矿层或营地，另一边完全不受影响 |
| 1 · 资源串联 | A 产出资源，B 消耗资源 | 矿层可以替换成“点击领取资源” |
| 2 · 战术反馈 | A 的结果改变 B 的选择，B 的局面反过来影响 A | 营地需求改变取牌优先级，工具和设施改变矿层可达性或风险 |
| 3 · 共享决策 | 同一次输入同时推进并牵制 A、B | 一次取牌同时改变叠层结构和营地胜负压力，无法拆成“先挖矿，再经营” |
| 4 · 新机制涌现 | 融合后产生母体单独没有的新技巧、风险与策略语言 | 玩家能学习并复现只属于“叠层矿场”的招牌技巧，而不再用“挖矿加经营”解释它 |

比赛原型若以“玩法融合”为卖点，通常至少需要达到 2 级。招牌动作最好达到 3 级。4 级不是必须追求的荣誉等级，只有当新策略能被玩家理解、练习并稳定复现时才成立。

给等级时，不要把短暂阶段切换当成失败。有些方案需要结算、商店或关卡过渡。关键不在界面是否同屏，而在决策后果是否跨阶段保留。反过来，即使两个系统同屏，如果玩家各自处理、互不牵制，它们仍然只是并排摆放。

《老虎机塔防》反驳了“上一阶段影响下一阶段就够了”的判断。它的早期候选让转出的符号成为下一波阵型，但如果塔防阶段主要自动播放，玩家在转轴阶段只追求更高伤害，关系会退化为“随机抽战力，然后观看结算”。要提高耦合，战场位置、敌人路线或上一波结果必须改变锁定与重转的判断，而且玩家要能干预结果。方案最终因融合浅和创新辨识度不足而暂不采用，这类淘汰比继续堆符号更节省成本。

## 3. 处理误判与范围

### 3.1 不要把融合度当成好玩度

融合度只回答“两个系统有多难拆开”。它不回答“主动作是否爽快”，也不回答“产品是否完整”。一个 1 级融合的游戏也可能很好玩：两个阶段各自优秀、节奏清楚、成长稳定，就能形成完整产品。一个 3 级方案也可能因为信息过载、操作别扭、结果不可预测而失败。

评价《叠层矿场》时，至少要分开三件事。

第一，融合深度。它看矿层和营地是否难以拆开。第二，核心乐趣。它看高频取牌是否产生期待、掌控与释放。第三，产品完成度。它看教学、压力、内容、胜负与重开结构是否成立。

这三件事的结论可以不同。某版《叠层矿场》可能只有 1 级融合，但取牌节奏清楚、成长稳定，因此作为轻经营游戏仍值得保留。另一版可能达到 3 级，却因为玩家同时追踪遮挡、配方、食物、金币、设施和风险而读不懂。此时问题不是“不够融合”，而是信息和操作没有被产品化。

《坠楼消除》反驳了“出现新高潮就等于好玩”的判断。它的设计高潮是玩家等待怪物聚集，完成最后一次横消，楼体坠落清场，同时棋盘永久变短。单独三消或单独塔防都不能产生完全相同的取舍。但它是否可读、是否好玩仍待试玩。当前只能说融合主张可以被明确验证。

### 3.2 跑偏后先改名字，再决定去留

混合原型可能没有兑现原来的宣传语，却意外形成另一种自洽游戏。判断跑偏方案时，不要直接判坏。先把两个问题分开。

```text
作为原定 A+B 方案，它符合目标多少？
作为实际形成的 C+A 方案，它是否值得独立保留？
```

回到《叠层矿场》：如果原目标是“叠层取牌和营地经营互相牵制”，但实际试玩只留下“叠层区提供随机资源，营地负责经营”，它作为原定融合方案不合格。可是它可能已经变成一种资源入口变体。此时要重新命名，并按新身份独立评价三件事：取牌是否本身有期待、掌控与释放。营地是否有清楚压力。两者是否有足够内容支撑重开。

如果新身份成立，可以分支保留。若团队仍需要参赛卖点“玩法融合”，就把原方案校准回 2 级或 3 级。若新身份不成立，且原融合目标也无法补强，就淘汰。这个结论比继续往矿层、营地和道具里堆规则更便宜。

《扫雷占城》反驳了“跑偏等于失败”的判断。它的原目标偏向快速领土吞并，但某版原型实际更像“扫雷生成道路的城池战争”：扫雷决定路线、瓶颈和侧翼，城池系统负责积兵与攻防。它对原目标的符合度有限，却可能比强行校准后的连续领土版本拥有更强的战术反馈。合理结论不是简单判坏，而是重新命名、独立评估，并决定校准还是分支保留。

## 4. 复查结论与来源

### 4.1 最后按一个顺序复查

通读方案时，按下面顺序问。不要跳到“像不像某个成功游戏”，也不要先争论好不好玩。

```text
两个母体各自承诺的核心体验是什么？
当前版本的唯一主动作是什么？
哪个系统制造局面，哪个系统兑现胜负？
主动作怎样同时改变两个系统？
系统 B 的结果怎样改变下一次主动作？
收益与代价是否由同一个可见状态承载？
删除一边后，另一边是否仍然完整？
把一边替换成领取按钮后，另一边是否基本不变？
两条反馈箭头是否都能在画面和操作中读出来？
哪个十秒高潮只有两者结合后才会出现？
融合后是否产生了新的可学习技巧？
```

前八问用于判断 0 到 3 级。最后两问用于区分 3 级与 4 级。若答案只能写成设定说明，玩家却不能在画面和操作中读出来，先不要增加第三个系统。优先补返回箭头：共享容量、共享空间、时间压力、工具反作用和信息公开都可以建立反馈，但每条关系都要改变玩家下一次主动作。
