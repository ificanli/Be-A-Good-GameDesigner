# 10 · 试玩观察：区分理解、实现与核心循环问题

本篇只完成一个阅读任务：试玩后把玩家反馈还原成可判断的行为证据，分清问题来自理解、实现、内容节奏，还是核心循环。

玩家说“不好玩”“没看懂”或“感觉怪”，不能直接告诉团队该改什么。观察者要先记录玩家经历了什么，再判断根因。分类错误会带来最常见的浪费：核心无聊时加教程，手感不稳时加成长，信息过载时加更多提示。

《五球满贯》在试玩阶段的关键不是收集“爽不爽”的票数，而是看玩家是否理解球路、墙加工和组合得分，是否在结算后主动改变下一杆。如果答案是否定的，还要分清是游戏没讲清楚、实现不稳定，还是这条循环本身缺少选择。

## 1. 保护首玩观察现场

### 1.1 首玩时先记录，不替游戏解释

首次试玩要让游戏自己说话。作者可以在测试后追问，但不应在玩家第一杆前补充规则。需要帮助时，记录触发点和帮助内容，因为那正是产品无法独立表达的证据。

观察重点不是玩家态度，而是行为顺序：他第一眼看哪里，第一次拖拽还是乱点，是否理解辅助线，哪次撞墙让他停顿，结算时是否知道分数来源，失败后是否主动重开。若作者解释一次后玩家立刻能规划球路，问题更可能在信息表达；若解释后仍然不用功能墙，就要怀疑核心激励或规则关系。

### 1.2 先写玩家动词链

不要用系统名称概括体验。把实际过程写成动词链：

```text
观察球位
→ 拖拽瞄准
→ 发射数字球
→ 等待碰撞停止
→ 查看墙加工结果
→ 读取组合槽
→ 决定下一杆目标
```

标出高频动作、真正需要判断的动作、反馈最强的动作，以及等待、确认、整理等行政操作。如果《五球满贯》的主要时间都花在等球停、读不懂结算和确认奖励上，而主动规划只出现一次，那么增加徽章不会解决节奏问题。

《叠层矿场》也可以用同样方法反查：点击裸露矿牌、等待三合、选择材料、点击矿工、继续取牌、用工具移除岩石。若玩家大部分时间在整理与等待，所谓经营深度就需要重新证明。

## 2. 解释反馈根因与体验维度

### 2.1 用四类根因解释同一句反馈

理解问题表示规则可能成立，但玩家没有看见可操作对象、状态变化或目标。证据是解释一次后，玩家立刻能够运用并产生选择。《五球满贯》中，玩家不知道被染色的是哪颗球，或不知道组合槽为何得分，应先修信息层级、渐进教学和反馈关联。《叠层矿场》第一屏同时展示多个区域，玩家还未取第一张牌就要理解生产系统，也属于信息负荷问题。

实现问题表示玩家知道想做什么，但输入、物理、镜头或界面无法稳定表达意图。《五球满贯》若实际球路与辅助预测不一致，失败不能归咎于空间判断。应先统一模拟、调节力度和停止节奏，再测试策略。

内容与节奏问题表示核心动作有趣，但出现频率、难度阶段或奖励节奏不合适。证据是玩家能指出最有趣的瞬间，却要经历过长空窗才能再次发生。此时可以调整桌面、生成规则、目标分和压力曲线，不必重写核心。

核心循环问题最严重：玩家理解规则，操作也稳定，仍然没有值得权衡的选择，重复十次后的局面和策略基本不变。此时增加提示、特效和内容只会包装薄弱结构。需要改主动作、缩短回报、加深系统反馈，或停止。

### 2.2 用体验维度连接观察和结论

诊断时可以沿五个维度复查，但不要把它们当评分表。每个维度都要落回具体行为。

| 维度 | 观察问题 |
|---|---|
| 即时反馈 | 输入后是否立即发生可理解变化 |
| 期待与释放 | 是否经历准备、承诺、不确定与兑现 |
| 掌控与技巧 | 熟练玩家能否有意识地得到更好结果 |
| 成长拐点 | 后期是否出现新路线和新判断 |
| 失败归因 | 玩家是否知道错在哪里、如何恢复 |

在作者本人对多个原型的横向试玩中，《五球满贯》的弹射和一杆多撞获得了最明确的“爽”感，因此被视为优先保护、继续验证的资产。这是个人体验与有限反馈，不代表广泛玩家结论。结算高潮、功能墙规划率、长局平衡与内容持续性仍需分别取证。

## 3. 把提问和记录转成复测

### 3.1 让提问服务证据

试玩后的问题应追踪因果，而不是索要喜好结论。可以问：你觉得核心规则是什么；哪个瞬间最有意思，之前做了什么准备；哪里最困惑或最烦；你为什么赢或输；如果立刻再玩，你会改变什么；如果只能改一个地方，你会改什么。

玩家的解决方案只作为线索。多人都说“加自动整理”，根因可能是库存行政负担过重，不一定真的需要自动按钮。玩家说“随机性太大”，在《五球满贯》中可能是物理预测不一致，也可能是桌面目标没有给出可规划路线。研究者要结合录像、操作日志和追问，找到他在哪个具体状态产生这种感受。

### 3.2 把反馈写成可复测问题

处理记录可以使用这张表：

```text
玩家原话：
发生时的局面：
玩家刚刚执行的动作：
预期结果与实际结果：
观察到的行为证据：
根因假设：
准备怎样复测：
```

优先修复三类问题：阻断完整局的问题，污染核心判断的问题，多人重复出现的问题。单个玩家提出的新模式、联机或大量内容不应立即进入范围。每次修改都要写明预期改变的行为，并安排复测；否则团队只是在积累功能。
