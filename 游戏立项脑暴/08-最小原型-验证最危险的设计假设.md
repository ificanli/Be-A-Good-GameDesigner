# 08 · 最小原型：验证最危险的设计假设

原型不负责缩小实现整份策划案。它的任务是以最低成本获得一项决策证据：某个关键假设更可能成立、失败，或目前仍无法判断。若原型包含大量外围功能，测试者的反馈反而难以归因。

## 先找最危险的假设

最危险不等于实现最困难，而是“一旦失败，整个方案就失去成立理由”。《五球满贯》的早期核心不是八轮内容和十二枚徽章，而是弹射是否可控、一杆多撞是否有反馈，以及通过球路收集组合素材是否值得规划。《坠楼消除》的核心则是消除支撑、楼体坠落和永久缩短棋盘能否形成可读取舍。

可以按以下顺序选择：

1. 失败后会不会推翻核心卖点；
2. 当前证据是否最弱；
3. 是否能用较小原型观察；
4. 测试结果能否导向明确行动。

## 把主张转换为测试任务

“加工链很有趣”应改为可观察任务：玩家第一次吞入武器后，能否说出弹药经过了哪些组件；是否会为了尾部射击方向改变移动；拿到增幅与复制后，能否预测不同顺序的结果。

测试任务应包含：

```text
目标行为：希望玩家做什么
测试局面：什么状态能触发该行为
观察指标：怎样判断玩家理解或使用
通过门槛：多少人、多少次或什么结果
失败行动：修改表达、修改规则还是停止
```

## 选择合适的保真度

原型的保真度不是统一的。与假设无关的部分可以非常粗糙，直接影响判断的部分必须足够真实。

- 验证物理手感：碰撞、速度、输入延迟与反馈要接近目标；
- 验证经济循环：可以用表格与回合模拟，不需要美术；
- 验证界面理解：布局、信息优先级和交互状态要真实；
- 验证内容组合：可用卡片、纸面状态或规则脚本。

灰盒不是所有东西都随便。若辅助线漂移，玩家无法判断是弹射思路有问题，还是实现不可靠。

## 原型只保留完整因果链

“最小”不能把关键后果删掉。《坠楼消除》若只实现三消削支撑，却没有楼体坠落、怪物清场和棋盘缩短，就无法验证核心取舍。应删除外围成长，但保留从输入到长期后果的完整链：

```text
交换并消除
→ 支撑受损
→ 楼体坠落清怪
→ 棋盘与防线变短
→ 下一轮压力改变
```

原型范围的单位应是“可验证因果链”，而不是功能数量。

## 建立测试接口

可重复的原型应允许快速重置、进入关键状态并记录结果。测试接口可以包括固定随机种子、跳转局面、调节速度、输出事件日志和暴露规则函数。它们不属于正式玩家功能，却能减少每次测试的准备时间，并支持回归检查。

《五球满贯》的阶段验收曾指出核心函数封装过深，难以自动验证复制墙、染色墙和爆仓逻辑。可测试性若完全留到最后，规则改动会越来越难复查。

## 运行一次假设驱动测试

假设《扫雷占城》要验证“扫雷方向会成为战争路线选择”。可以固定一张包含两条路线和中央城的地图，让玩家在相同兵力下完成两局。记录首个探索方向、踩雷后的调整、是否为抢中央城承担更高风险，以及敌军反用道路时的反应。

如果玩家只把翻格当传统扫雷，出兵是在地图打开后才开始的第二阶段，说明融合证据不足。下一步应调整地图、兵力成本或道路争夺，而不是增加技能。如果玩家确实围绕战线选择翻格，才继续测试不同地图和 AI 下能否复现。

## 控制变量与人为保护

原型可以固定掉落、安排教学球路或保证首个组合出现，但要把保护条件写出来。受控开局证明的是玩家在理想条件下能否理解核心，不证明随机生成和长期节奏已经成立。随后应逐步撤掉保护，观察行为是否保持。

一次测试尽量只改变一个关键关系。若同时重做输入、数值、教学和美术，即使反馈改善，也难以判断哪项修改有效。

## 三种结果

### 通过

目标行为在预设条件下稳定出现，可以进入完整局或下一项风险。通过不表示项目已立项，只表示一个假设获得支持。

### 失败

玩家理解后仍不愿使用，或核心结果无法在预算内实现。应修改结构或淘汰，不宜先加奖励诱导。

### 无结论

测试被实现缺陷、教学干扰、样本不合适或局面不足污染。无结论不能写成“初步通过”。需要修复测试条件后重做。

## 最小原型说明页

```text
本原型只验证：
不验证：
核心假设：
保留的完整因果链：
人为受控条件：
观察任务：
通过门槛：
失败与无结论的区分：
测试后允许增加的下一层内容：
```

这张说明可以防止试玩者把缺失的产品功能误当成当前问题，也防止团队用原型已完成为理由继续扩建。
