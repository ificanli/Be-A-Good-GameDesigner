# 00 · 立项不是先想玩法

游戏立项常从一句玩法描述开始，但同一玩法放在三日比赛、半年独立开发和长期运营产品中，会得到完全不同的方案。开始脑暴前，应先明确项目要解决的问题、受到的限制，以及需要取得的证据。否则，会议只会堆出一批无法比较的点子。

## 约束会改变可选机制

平台、输入、周期和团队能力不是创意完成后的制作问题。`NewGame` 的初始条件包括三日开发、源码提交、直接打开 HTML 可玩、桌面键鼠、无服务器与外部依赖。这个条件排除了依赖大量关卡、实时联网和复杂素材生产的方向，也使网格、卡牌、弹射与确定性物理更适合作为候选。

| 类别 | 需要明确的内容 |
|---|---|
| 用户与场景 | 谁在什么设备上，以多长时间游玩 |
| 产品目的 | 比赛展示、商业产品、作品集还是研究原型 |
| 制作能力 | 人数、周期、技术、美术和内容产能 |
| 运行边界 | 平台、输入、联网、性能与审核要求 |
| 决策门槛 | 何时可试玩、何时可立项、何时停止 |

约束必须具体到能排除方案。“开发周期短”没有筛选能力；“第三天必须形成可直接打开、包含胜负和重开的三分钟完整局”才有。

## 分开写体验目标与产品目标

体验目标描述玩家在游玩中反复经历什么。例如《五球满贯》希望玩家规划球路，一杆连续收集数字球，再决定结算或继续冒险。产品目标则要求这段过程能在短时间内被旁观者看懂，并形成完整比赛 Demo。

两者不能互相代替。第一次操作很爽，不代表能支撑多局；具备成长与商业接口，也不说明核心动作有趣。立项页应分别记录：

- 第一次输入产生什么即时反馈；
- 玩家每 3～20 秒做什么判断；
- 单局如何升级压力并结束；
- 多局之间为何不同；
- 新内容通过什么接口加入；
- 哪些内容只是未来可能性，不进入当前验证。

## 把卖点改成可证伪假设

“扫雷与占城结合很有策略”无法验证。可以改写为：玩家会把“向哪边扫”理解为抢夺道路，并在安全绕路、冒险开捷径与争夺中立城之间做选择。随后才能定义观察项：首局三分钟内，玩家是否因探索的兵力成本改变方向；敌人利用公开道路反攻时，玩家能否解释原因。

每个候选至少应写三类假设：

1. **理解假设**：玩家无需作者解释，能否说出目标与主要操作。
2. **体验假设**：高频动作是否产生预期的掌控、风险或释放。
3. **生产假设**：核心效果能否在预算内稳定实现。

假设还要有停止条件。例如五名首玩者中，若多数人在三分钟内没有主动利用特殊墙规划球路，就应先修改规则表达和路径可控性，而不是增加徽章与关卡。

## 区分设计主张与验证结果

立项会上容易把策划案中的完整描述误当成已经成立。可以把证据分成四级：

- **设计主张**：逻辑上可以解释，但尚未运行；
- **已经实现**：规则在原型中能够工作；
- **试玩观察**：目标玩家确实理解并使用；
- **稳定复现**：多轮测试和不同局面下仍出现预期行为。

《贪吃蛇军火库》的某版原型已经实现弹药沿身体加工、三槽尾仓与精准尾射，因此只能记为“规则已实现”。目前反馈主要来自作者试玩，交接文档仍要求观察外部玩家能否复述加工过程、主动调整尾向并预测组件顺序，所以不能提前声称构筑深度或普遍乐趣已经得到验证。

## 立项起始页

```text
项目目的：
目标玩家与游玩场景：
平台、输入和单局时长：
制作周期与资源：
体验承诺：
最危险的三项假设：
每项假设的最低验证方法：
通过门槛：
停止条件：
明确不做：
```

完成这页后再生成候选，脑暴才会围绕同一个问题展开。后续淘汰也有明确依据：被否决的是方案与约束不匹配，而不是对灵感本身作价值判断。

## 示例：同一创意在不同约束下会变成不同项目

假设初始概念是“通过撞击收集对象，并组成组合”。如果目标是三日比赛，验证重点应是撞击手感、对象可读性和一次组合高潮，内容只需支撑短局。如果目标是移动端商业产品，还要补充单指输入、单局中断恢复、重复开局、内容更新成本和付费边界。如果目标是强调空间技巧的独立游戏，则可以接受更长学习时间，但必须提高轨迹可控性和关卡变化。

因此，候选评分不能脱离项目约束。某个方案因三天无法实现而被淘汰，不代表它在其他条件下没有价值；同样，一个适合比赛展示的强画面，也不自动具备长期内容空间。

## 开会时怎样使用这张起始页

第一轮会议先确认约束，不讨论具体方案。第二轮要求每个候选使用同一格式描述体验承诺和三项假设。第三轮只比较证据成本：哪个假设最危险，最快需要几小时或几天才能获得结果。此时还不评审完整系统。

会议结束应留下三项产物：统一约束页、候选假设表和下一轮最低成本验证清单。若会议只留下十几个玩法名字，说明讨论尚未进入立项工作。
