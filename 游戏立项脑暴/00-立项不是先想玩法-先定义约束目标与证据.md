# 00 · 立项不是先想玩法

立项会常从一句玩法开始。“台球加构筑”“扫雷加占城”“贪吃蛇加武器”听起来都能继续展开，但它们在三日比赛、半年独立开发和长期运营产品里，会变成完全不同的项目。若团队先讨论灵感，再回头补条件，会议里产出的只是一批无法比较的名字。

更可靠的顺序是先确定约束，再写体验承诺和产品目标，最后把卖点改成可证伪假设。候选被保留或淘汰，应该因为它是否匹配这组条件，而不是因为某个点子听起来更酷。

## 1. 定义立项输入

### 1.1 先写能排除方案的约束

约束不是创意完成后的制作问题。`NewGame` 的初始条件包括三日开发、源码提交、直接打开 HTML 可玩、桌面键鼠、无服务器与外部依赖。这些条件会立刻排除依赖大量关卡、实时联网和复杂素材生产的方向，也会把网格、卡牌、弹射与确定性物理推到更合适的位置。

“开发周期短”没有筛选能力。它只表达焦虑，不改变决策。“第三天必须形成可直接打开、包含胜负和重开的三分钟完整局”才会迫使团队放弃庞大的内容生产，优先验证一个清楚的短局循环。

起始页至少要写清五类约束：用户与游玩场景、产品目的、制作能力、运行边界和决策门槛。每一类都要具体到能排除方案。例如目标是比赛展示，旁观者能否在短时间内看懂就会成为产品目标；目标是研究原型，则可以接受粗糙素材，但不能省略关键变量记录。

### 1.2 再分开写体验目标和产品目标

约束回答“什么不能做”。目标回答“这次必须证明什么”。这两件事也要分开写。

以《五球满贯》为主要案例，体验目标是让玩家规划球路，一杆连续收集数字球，再决定结算或继续冒险。产品目标则不同：它需要在短时间内被旁观者看懂，并形成一个完整比赛 Demo。第一次撞球很爽，只说明即时反馈可能成立；它不证明单局能升级压力，也不证明多局有差异。

因此，立项页不能只写“台球构筑，很有策略”。它要把体验拆成玩家行为：第一次输入产生什么反馈；玩家每 3～20 秒判断什么；单局如何增加压力并结束；下一局为什么不是重复；新内容通过什么接口加入；哪些内容只是未来可能性，不进入当前验证。

这一步的规则—行为—观察—结论链应写成这样：规则让数字球、颜色、特殊墙和五球容量共同改变路线价值；玩家因此在出杆前比较不同球路；测试时观察玩家是否会因为组合、爆仓或特殊墙主动改线；若多数人只按最近球乱撞，就不能说“构筑已经进入台球操作”。

## 2. 把想法转成证据

### 2.1 把卖点改成可证伪假设

卖点用于沟通，假设用于立项。“扫雷与占城结合很有策略”无法验证。更好的写法是：玩家会把“向哪边扫”理解为抢夺道路，并在安全绕路、冒险开捷径与争夺中立城之间做选择。

写到这里，团队才能定义观察项。首局三分钟内，玩家是否因为探索的兵力成本改变方向；敌人利用公开道路反攻时，玩家能否解释原因。若这些行为没有出现，问题可能在规则表达、反馈强度或目标压力，而不是宣传语不够有吸引力。

每个候选至少写三类假设。理解假设检查玩家无需作者解释，能否说出目标与主要操作。体验假设检查高频动作是否产生预期的掌控、风险或释放。生产假设检查核心效果能否在预算内稳定实现。

假设还需要停止条件。以《五球满贯》为例，若五名首玩者中，多数人在三分钟内没有主动利用特殊墙规划球路，就应先修改规则表达和路径可控性，而不是增加徽章、关卡和成长线。

### 2.2 给每条判断标注证据等级

立项会上最常见的误判，是把策划案里讲得通的系统当成已经成立。证据至少要分成四级：设计主张、已经实现、试玩观察、稳定复现。

《贪吃蛇军火库》的某版原型已经实现弹药沿身体加工、三槽尾仓与精准尾射，所以“规则能运行”可以记为已经实现。但当前反馈主要来自作者试玩，交接文档仍要求观察外部玩家能否复述加工过程、主动调整尾向并预测组件顺序。也就是说，它还不能提前声称构筑深度或普遍乐趣已经得到验证。

这条边界同样适用于《五球满贯》。策划案可以解释为什么特殊墙会改变球路，作者试玩也可能感到一杆连收很爽，但只有目标玩家在无讲解时反复利用这些规则，才能把结论从设计主张推进到试玩观察。多轮测试和不同局面下仍出现预期行为，才接近稳定复现。

## 3. 用证据推进会议

### 3.1 写完起始页，再生成候选

起始页可以很短，但字段必须服务决策。

```text
项目目的：
目标玩家与游玩场景：
平台、输入和单局时长：
制作周期与资源：
体验承诺：
最危险的三项假设：
每项假设的最低验证方法：
通过门槛：
停止条件：
明确不做：
```

这页完成后，脑暴才围绕同一个问题展开。被淘汰的方案也有明确理由：它与约束不匹配，或最危险的假设无法用当前资源验证，而不是灵感本身没有价值。

同一个“通过撞击收集对象，并组成组合”的初始概念，在不同约束下会变成不同项目。三日比赛应验证撞击手感、对象可读性和一次组合高潮，内容只需支撑短局。移动端商业产品还要补充单指输入、单局中断恢复、重复开局、内容更新成本和付费边界。强调空间技巧的独立游戏可以接受更长学习时间，但必须提高轨迹可控性和关卡变化。

### 3.2 会议按证据成本推进

第一轮会议只确认约束，不讨论具体方案。第二轮要求每个候选用同一格式描述体验承诺和三项假设。第三轮只比较证据成本：哪个假设最危险，最快需要几小时或几天才能获得结果。

会议结束应留下三项产物：统一约束页、候选假设表和下一轮最低成本验证清单。若会议只留下十几个玩法名字，说明讨论还停在创意收集，没有进入立项工作。
